# Anthropic 付得起算力账，但填得满算力吗？

> 原文：[Anthropic Can Pay for the Compute. Can It Fill It?](https://medium.com/@adriel.frederick/anthropic-can-pay-for-the-compute-can-it-fill-it-4c6a784ff990) — Adriel Frederick

---

Anthropic 在 10 月 26 日递交了 S-1 招股书。第二天早上，头条新闻已经选好了它们的数字：7500 亿到 8000 亿美元之间的基础设施承诺，以及上半年 800 亿美元的净亏损。再加上一份长得看不到头的风险因素章节，一个「公司在花自己没有的钱」的现成叙事就齐活了。

作者 Adriel Frederick 是 Claude 的重度用户——200 美元/月的 Max 套餐经常用满 90% 额度，大部分花在 Claude Code 上。他选择去读招股书里自己在意的部分，对着文件校验自己的假设，然后写下这篇整理自己真实判断的文章。他的视角很窄：这门生意要持续增长而不崩掉，两件事必须同时成立——**Anthropic 得在不承诺超出支付能力的范围内锁定足够算力；还得把更多种类的知识工作变成真正消耗这些算力的、可复购的付费负载**。算力容量问题比 8000 亿头条暗示的更可控。产品采用问题才是真问题。

## 生意本身是运转的

在吓人的数字之前，先看要紧的：

- **营收在快速复利**。2026 年一季度约 47 亿美元，二季度 116 亿美元。S-1 止于 6 月，但 Anthropic 向 IPO 投资者透露三季度达到 168 亿美元。
- **毛利率已经翻转**。按公司功能成本口径，毛利率从 2025 上半年的约 12% 升到 2026 上半年的约 85%——研发与渠道成本不在其中，不是全貌，但方向无可争辩。
- **二季度实现了营业利润**。约 10 亿美元 GAAP 营业利润，8% 利润率。上半年整体仍是小幅经营亏损。
- **在产生现金**。上半年经营现金流约 39 亿美元。
- **家底厚**。6 月 30 日持有约 1320 亿美元现金与短期投资——大部分来自投资者而非经营，但确实在那里。

那 800 亿亏损从哪来？几乎全部来自「谁拥有什么」的会计处理。Anthropic 历年通过可转债、SAFE 等协议融资，这些工具日后会转成股票。公司估值飙升时，投资者将获得的股票大幅升值，会计规则要求把这部分升值记为亏损：上半年约 810 亿美元的 charge。这是关于「谁持有 Anthropic 股份」的记账，不是流出生意的真金白银。剔除后上半年大致盈亏平衡。

但并非所有非现金 charge 都是噪音。有两项是真成本，都源于用股票支付人力：股票薪酬上半年约 22 亿美元，年年发生，已含在上面的数字里；IPO 还会叠加一次性冲击——大量员工持有的限制性股票单元（RSU）要到公司上市才归属，IPO 时点要一次性把员工已挣得的部分全部入账，按 6 月 30 日口径约 29 亿美元，其后约两年还有 237 亿美元。**预期 IPO 后的 GAAP 报表会更难看，理由与底层生意无关。**

## 8000 亿头条的背后

作者没料到的是：算力计划比头条听起来更有章法——它像是为灵活性和不确定性设计的，不像一家押上全部身家赌单一预测的公司。

- **不从一个地方、按一条时间线买算力**。承诺分散在 Microsoft、Google、Amazon、SpaceXAI、Nscale、Lambda、Broadcom 和 AMD，起止时间各不相同；芯片跑在 Google TPU、Amazon Trainium、NVIDIA GPU 上，AMD 2027 年加入。分散是谈判筹码，也是把工作迁去最便宜处的余地。
- **最聪明的一块叫 Anthropic Direct**。不只从云厂商租现成容量，而是直接租芯片，放在由 Fluidstack 等伙伴代建代运营的专用设施里。这把通常捆绑的两个决策拆开了：锁定楼和电力——排期最慢但占成本较小份额；选机柜里的芯片——占大头且一两年一换。**早锁定慢的部分，晚下注贵的部分。**
- **供应商同时是股东**。Amazon 和 Google 不只卖算力，还通过 Bedrock 和 Google 的智能体平台把 Claude 转售给自己的云客户；可转债与优先股在 IPO 转换后，各自持股将超 5%。两者都还有绑定算力里程碑的后续资金：Amazon 至多 150 亿、Google 至多 200 亿，以股票或票据支付。Broadcom 有类似安排——必要时 Anthropic 可向其发行至多 420 亿美元可转债支付设备租金刚性支出；连 AMD 都同意在满足特定条件时购入至多 50 亿美元股票。

卖你芯片的、转售你产品的、你股东，是同一家公司——所有人同输赢。反面是部分钱在绕圈：伙伴投资，投资的一部分又作为算力支出流回伙伴。OpenAI 与 Microsoft、NVIDIA、AMD、Oracle 之间有同款网络。「我不确定这些关系有多健康。」

这一切成立的前提，是 Anthropic 同时做好三件事：以好价格买算力、从每个芯片小时里榨出更多有用工作、让机队保持忙碌。多平台运行对三者都有帮助，但不担保任何一个。

## 灵活性买不到的东西

**签了就是欠的。** 把楼和芯片分开只在承诺之前有帮助；之后就是义务。随 S-1 备案的 Broadcom 设备租约除特定情形外不允许取消订单，且基本上无论发生什么租金照付，有些款项甚至在设施延期时就开始支付。不过并非一切锁死全周期——最大的单笔交易，与 SpaceXAI 至多 1205 亿美元——初始期 2027 年初结束后，任一方提前 90 天通知即可取消。

**闲置容量依然昂贵。** 作者本能是：需求不及预期就熄灯省成本。行不通。Epoch AI 为一个通用 1GW NVIDIA 数据中心建的成本模型显示，服务器加网络占年度成本近四分之三，电力只占约 7%——关灯省下电费，其余大头照来。

**转售有效，直到所有人都在卖。** 闲置容量可以找下家——今年早些时候 Anthropic 包下了 SpaceXAI 的 Colossus 1 全部容量，说明大块算力确实易手。卖不掉总比全额吃下强，但这只在市场紧俏时成立。「今天确实紧俏。我仍认为整个行业大概率处于某种过度建设状态，只是要等现在建的容量上线才会显形。」

这与互联网光纤潮押韵。美国几乎每次大型基建都伴随过度建设：铁路、公路、宽带，现在是 AI。哥伦比亚大学的 Stijn Van Nieuwerburgh 在 Brookings 播客里给出了量级：他的论文估算 AI 数据中心建设到 2032 年每年约占 GDP 的 3.6%——铁路狂热峰值约 2.2%，洲际公路与电信光纤各约 1.1%。Gartner 本月更激进：预计到 2030 年 AI 基础设施支出约 7 万亿美元，而相关收入至多 3.6 万亿，若供应商维持当前节奏，超 3.5 万亿支出可能面临减记。90 年代铺的光纤最终被用上了——许多铺光纖的公司没能活到那一天。

作者出于好奇把 S-1 里点名合同逐年排了一遍（招股书自己的年度付款表是空白，这是他的粗模型）：总额约 7950 亿美元，与头条一致，2028 与 2029 年达峰约每年 1250 亿。

## 那么要赚多少钱才背得动？

二季度，算力与基础设施约占营收 48%，其余（人员、销售与渠道、管理费用）约 43%，营业利润率 8%。把建模的付款当作全部算力账单、其余成本随营收等比增长来算：三季度 168 亿年化约 670 亿美元。结论：

- **2027 年，Anthropic 需要约 3 倍于当前 run rate 的营收才能保本，3.5 倍才能保住二季度的利润率。**
- 换成公司语言：今天 Anthropic 约合 IBM 的体量（年营收约 670 亿）。2027 保本意味着长成 Meta 的体量（约 2000 亿），保利润率意味着超过 Nvidia。按今年财富 500 强，约两年内从第 66 位升到全美营收第 15-19 名之间。
- 2028 需要约 3.3 至 3.9 倍。换句话说，从 2026 年三季度到 2027 年底，**营收得每个季度增长约 34-39%，连续五个季度**。三季度本身增长了 45%，所以 pace 够得着——但增长已在放缓：从二季度的 144% 降到三季度的 45%，而这一切要在更大的基数上再跑五季。

经营杠杆能帮忙：若人员与管理费用远慢于营收增长，保本点降到约 1500-1700 亿；2027 年初后砍掉 SpaceXAI 可为 2028 年账单减负至多 370 亿。另一面，这张表漏了未单列的设施租约、Broadcom 租约利息和任何新合同。这些是数量级估算，不是目标。

**需求不及预期时付得起吗？** 作者做了粗压力测试：假设营收停在当前 670 亿 run rate、其余成本保持二季度占比——到 2027 年底，表内合同需要比营收多出约 870 亿美元，1320 亿现金覆盖得住；到 2028 年缺口扩至约 1750 亿，仍在已排好的弹药（现金 + 新 150 亿授信 + Amazon 150 亿额度 + Broadcom 至多 420 亿票据，合计约 2050 亿）之内；到 2029 年达到约 2650 亿，那是全面停滞需要新钱的地方——除非 2027 年初后放弃 SpaceXAI，缺口回到约 1750 亿。IPO 募资再加一层余地。**所以：付得起。就算增长明天停止也有两年多的缓冲。这正是需求问题更要紧的原因。**

## 价格：token 是错误的单位

定价争论大多纠缠在每 token 价格上——「另一个模型同智能水平便宜 25%」仿佛能一锤定音。

作者去年秋天把 AI 基础设施比作油气，这个类比在这里依然成立：**token 像原油桶。每桶计量方式相同，价值并不相同。** 轻质低硫原油硫少易炼，变成汽油柴油更省工，卖溢价；重质高硫原油要多道工序才能出同样产品，折价交易。石油行业没人相信一桶就是一桶。第一次就把任务做对的模型的 token 是轻质低硫；需要重试和大量人工核验的便宜 token 是重质高硫——每桶付得少，炼厂付得多。

作为客户真正要看的数字是**「我能接受的一个完成任务的总成本」**：模型加工具加集成加我审查的时间加重试再加失败的那几次，除以做对的任务数。一个要试三次、还搭上一小时监督的便宜模型并不便宜。

Anthropic 称 Opus 5.5 相对 Opus 5 通过降价与效率提升把客户每任务成本砍了约 40%，且未伤及自身毛利——这是管理层说法，招股书未按模型拆分盈利，但与作者自身体感一致：每 token 价格大降，任务成功率全面上升，重试购买大幅减少。「每任务成本才是该量的东西。」

价格在朝对的方向走。但营收的陷阱在这：每任务成本下降时，Anthropic 每任务赚的也变少。所以 3 到 3.5 倍必须从量里来，还得有富余。这就是赌注：**任务便宜得多，任务数量多得多。AI 不是在和其他 AI 打价格战，是在和「把知识工作做完的成本」竞争**——更便宜的工作让一些从前没人愿意雇人做的活变得值得做。这个量会不会出现，才是真问题。

## 数量：填得满容量吗

产品和伙伴能不能把足够多的知识工作种类，足够快地变成持续、有价值的负载，去吸收即将上线的算力？作者认为答案要靠围绕具体工作流构建的产品，而不是更好的聊天。

**Claude Code 为什么奏效。** 去年秋天他就论证过：胜出的 AI 工具不是更好的聊天机器人。Code 解决上下文问题的方式是住进工作发生的环境里——看得见项目、改得了代码、跑得起来、测得过去，交回一份可审查的成果。编码还有内建的反馈环：测试通过不等于正确，但它让智能体持续前进、自我纠错，不必每步都来问人。

S-1 里有一个数字指向这个方向：**不用 Code 的 Claude Enterprise 用户月均花费不到 75 美元，而用 Code 的头部 5% 用户花费约是 20 倍**。无论营收怎么拆分，这就是「深度产品」的样子。

**深度的定义。** 对编码以外的一切，产品必须把「委托」变具体。深度产品为一个可辨识的工作单元负责：月末关账、合同红线批注、安全事件调查、产品实验复盘。对其中任何一个，四个问题要有好答案：我能交出去什么（有明确责任人、触发器和预算的周期性工作）；它需要知道什么（从源记录与既往决策可靠组装的上下文，以及框定——哪个源是哪个问题的真相）；它能做什么（在工作所在的系统里获得行动权限，带合理的审批点）；我拿回什么、怎么知道它是对的（真实产出——对平的账、可供决策的分析——加上把错误最先暴露的校验、一个人扛得动的审查量、需要判断力时的干净交接）。

**陷阱是「便宜的首稿」。** 如果收集上下文和检查结果仍吃掉大部分时间，首稿几乎没省任何东西。产品必须砍掉完成整件工作的总成本。

作者正在用自己的副业项目——一个家庭事务整理器——亲历这四个问题：家庭一周的事实散落在邮件、日历和短信里，接不上 iMessage 或 WhatsApp 就看不全也动不了；「框定」是最意外的一难——邮件里的生日邀请不代表要去，除非它上了日历；而妻子在日历上给活动标的时间不是事实，组织者的邮件才是真源。Code 是走了运的：上下文住在一个地方，文件即真相，测试告诉你行不行。**大多数工作不以这种方式打包。**

## 谁来建

两条路，不互斥。**Anthropic 自建**：更多像 Code 的产品，研究与产品团队贴近，把新模型能力快速变成有用的工作。招股书里有个看似打脸作者直觉的数据点：截至 9 月 30 日，Cowork 的采用速度超过了 Code 同期——作者认为对比有误导性：Cowork 内置于已有庞大装机量的 Claude 桌面应用、9 月已开始合并进主应用，而 Code 是用户得自己发现并安装的终端工具。「给已装应用的人推的功能，去对比一个必须挣来全新安装的产品，不是同类比较。」而且那是采用率，不是留存支出或完成的工作量。

**伙伴来建**：软件公司、创业公司、咨询公司和企业在 Claude 上构建会计、法律或运营产品——它们往往已有分发、数据接入和信任。客户买的是会计产品，从不需要单独决定买 Claude，而 Anthropic 照样卖算力。上行是广度：大量团队并行建设。风险是价值留存：伙伴拥有客户、可以把工作路由给别的模型、议价，并拿走大部分应用层毛利——**token 量在涨，经济性可能在变差。**

两个维度其实是四象限：产品多宽，和谁拥有它。Anthropic 完全可以自运营一个在部分领域有深度工作流的宽应用，同时让伙伴拥有另一些领域的专用产品。大概率终局如此。代价在于：每一个领域都需要真实的功夫去理解、集成、赢得信任——更好的模型不会替你交付其中任何一样。

## 我在盯什么

头条数字回答不了这些问题。这些可以：

- **量：编码之外的留存支出。** 不是试点，是一年后还在且还在增长的用量。
- **量：监督需求随时间下降。** 任务以更少重试、更少人工审查完成——这才让更多工作值得交出去。
- **价：伙伴经济学。** 扣除服务成本与商务条款后，Anthropic 在伙伴负载上实际赚到什么，而不只是 token 量。
- **两者：现金与容量同步到账。** 每一拨新算力上线时，是否有与之相配的营收一起出现。

剥掉 8000 亿和 800 亿，剩下的是一门增长极快、有真实利润率、在产生现金、算力计划比头条更有回旋余地的生意。余地不是无限的：签下的要还，闲置的昂贵，转售只在全行业不同时过度建设时有效。

作者的增长背景指向一个判断：**分发不是 Anthropic 的约束**——自家应用加上 Amazon、Google、Microsoft 转售，加上每天都在用的开发者，触达绰绰有余。约束是产品：它的产品能端到端接住多少种工作。「花了大量时间看这些模型能做什么之后，我认为那些产品是可能的。只是还没被造出来。」

真正的问题从来不是 Anthropic 付不付得起算力。**是我们要有足够多的工作，变成可以交给 Claude、并信任它交回来的东西。** 这也是上一篇《AI Didn't Take That Job》里岗位问题的更有用版本：填满这些容量的产品，多半不是把人整体替换掉的那种，而是接走一块真实工作、做完、亮出校验、把判断交还给人的那种。Code 证明了当工作能自我校验时模型就能干活。Anthropic 的账单，取决于我们其余的工作有多少能学会做同样的事。

# 《Anthropic Can Pay for the Compute. Can It Fill It?》的发芽报告

## 材料核心

Adriel Frederick 拆解 Anthropic S-1 后给出一个反直觉的排序：8000 亿美元算力承诺和 800 亿美元净亏损这两个吓人头条，前者是比头条更有章法的多供应商、多芯片、楼芯分离的灵活性设计，后者主要是可转债会计记账（810 亿）而非现金流出——真实的风险敞口远小于标题。付得起有两年缓冲验证兜底，因此真正的赌注不在资金端而在需求端：把足够多的知识工作变成「可以交给 Claude 并信任其结果」的可复购负载。价格端 token 是错误的单位，每任务成本才是；数量端的证据在 Claude Code（不用的企业用户月均 75 美元以下，用的头部 5% 花费 20 倍），路径是「接走一块真实工作、做完、亮出校验、把判断交还给人」。

## 发芽 01：把「楼和芯片」拆开签约——先锁慢的便宜的，晚下注贵的多变的

### 种子

大额长期采购里往往混着两种性质完全不同的决策：一种又慢又便宜但一旦落成就难改（楼、电力、机位）；一种又贵又善变但每年都有新选项（芯片型号）。Anthropic Direct 把这两者拆开分别签约。

### 故事

数据中心建设要排队多年，但只占成本的小头；芯片占大头却一两年一代。于是 Anthropic 直接租芯片、让 Fluidstack 等伙伴代建代运营设施：楼和电力的长期约束早早锁定（反正它们便宜又不会换代），芯片这个每年都在变化的大额变量留给未来——等自己知道得更多时再选。与之配套的是全供应商分散：八家供应商、四种芯片、起止时间交错，还有「签了就欠」的边界（Broadcom 租约不可撤、闲置容量七成成本照付）和留出的活口（SpaceXAI 大单 90 天通知可取消）。

### Aha 瞬间

所谓「为不确定性设计」，不是预测得更准，而是**把合同按「变的速度」分层，让每一层的锁定期匹配它的变化速度**——慢而便宜的先锁死，贵而善变的留活口。这跟个人买电脑先定机箱电源、最后才选显卡是同一种智慧，只不过规模放大了一万倍。

## 发芽 02：原油类比——为什么「每 token 价格」是个误导性指标

### 种子

轻质低硫原油和重质高硫原油按同一口径计量（桶），炼化成本天差地别，所以油价从来分品质定价。token 也一样：一次做对的 token 和要重试三次、外加一小时人工核验的 token，计量单位相同，实际成本不同。

### 故事

市场争论停留在「同智能水平便宜 25%」，而客户真正负担的是「完成一个可接受任务的总成本」：模型 + 工具 + 集成 + 审查时间 + 重试 + 失败分摊，除以做对的任务数。Opus 5.5 每任务成本降 40% 的同时没伤毛利，说明便宜和品质可以在「任务」这个正确单位上兼得——而在 token 这个错误单位上，降价恰恰意味着单位收入下降。

### Aha 瞬间

**计量单位选错，整个优化方向都会跟着错。** 在 token 单位上，「降价」和「营收承压」看起来是矛盾；换到任务单位，降价、成功率上升、毛利保全、量能放大是同一件事的四个侧面。任何行业里，找到那个「客户真正购买的东西」作为计量单位，争论往往就消失了。

## 发芽 03：「接走一块工作、亮出校验、交还判断」——AI 产品的可复制配方

### 种子

Claude Code 成功的偶然条件：上下文住在一个地方、文件即真相、测试告诉你行不行。大多数工作没有这种打包。但配方本身可以从这三个条件里提炼出来，推广到月末关账、合同批注、安全调查等任何领域。

### 故事

四个设计问题的答案构成产品骨架：明确可交接的工作单元、从源记录可靠组装并框定真相的上下文、带审批点的系统行动权限、错误最先暴露的校验加一人可扛的审查量。作者用家庭事务整理器副业亲测每一问之难——邮件里的生日邀请不算数，日历上的时间也不是事实，真源判定本身就是设计问题。而证据在数据里：用 Code 的头部企业用户花费是不用者的 20 倍。

### Aha 瞬间

**「自我校验」是任务能否被 AI 接管的分界线，而不是「任务是否复杂」。** 编码先被攻克不是因为代码简单，而是因为它自带测试；意味着其他领域的破局点不是更强的模型，而是给每种工作造出它的「测试」——做完工作、展示证据、把最后的判断留给人。这个配方同时回答了岗位焦虑：产品接走的是工作块，不是人。
