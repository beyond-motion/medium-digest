# PR 瓶颈只是症状：agent 提出的工作，比问题需要的更多

> 原文：[The PR bottleneck is a symptom](https://medium.com/analysts-corner/the-pr-bottleneck-is-a-symptom-a9eba64f15f4)

---

## 我以为第一个爆掉的是评审队列

过去几个月，作者（Matt Whetton）的团队一直在给「工程团队与 agent 协作」套上更结构化的流程：五个阶段——意图（intent）、方案（approach）、实现（implementation）、签收（sign-off）、部署（deployment），agent 映射到每个阶段；按任务与工程师的不同，配四种与 agent 协作的模式。还有一条他们争论过但坚持下来的规则：**每个阶段必须同时适用于人和机器**——他们考虑过设计一个只有机器遵循的流程，最终认定那一步跨得太远。签收环节有一条他自认为最重要的检查：代码做的正是 backlog 条目说的，不多，不少。

他的预设是：标准就位后，第一个暴露出来的问题会是评审队列——agent 的产出超过人的评审容量，人人都这么说，他们的队列看起来也这么证明。

队列是真的。但问题不止在队列那里。

## 流程实际暴露了什么

在一个为客户设计银行卡交易授权系统的项目里，他们用 agent 协助设计。agent 态度坚决：需要一个独立于核心账户服务的专用授权服务。推理无懈可击——独立服务响应够快，还能干净地处理一组边缘条件。

但独立服务意味着「账户」存在于两个地方。于是提案自带了一套配套：跨域同步、证明两边视图一致的对账、以及捕捉漂移的检查。全部合理——全都是那种能作为「一份靠谱的工作」通过评审的东西。

团队把它推了回去，方案最终落在既有的核心账户能力上，外加让它够快所需的改造。整个设计就此结束：系统里少了一件需要「维持两处一致」的东西，几周的工程从未被建造。

让作者印象最深的不是 agent 提了这个方案——一个能干的工程师也可能提。而是：**推回发生在方案阶段，且当时有人在房间里。** 如果当时没有人，这份提案就会以代码的形式到来：二十个合理的 PR，每一个都单独可评审，每一个都在给那条他以为就是问题本身的队列添砖。

这就是他们反复看到的模式：不需要做的任务；简单问题配上精致答案；三倍于任何人会读的长度的文档。没有哪样是「错的」。他为签收写的「不多不少」检查，一直是真正要紧的那个检查——只是它放错了位置：**到了签收环节，「多」已经建成了。**

## 为什么没有任何东西推回

流程标准里写着：注意力在特定节点是高杠杆的，方案阶段就是其中之一。作者自己写的这句话，却仍然默认瓶颈在评审。他想明白了原因：和人共事时，方案阶段向来「自己照顾自己」。

当一个工程师提出独立服务时，他提的就是自己要建的东西——写同步的人是他，负责对账的人是他，半夜被告警叫醒的还是他。这个前景在提案出口之前就悄悄把提案编辑了一遍。**多年来他见过的人的过度工程，大多死在了提案者自己的脑子里**——因为出主意的人就是扛活的人。

而提出独立服务的 agent，这些成本一样都不沾：它不以任何「会让它付出代价」的方式去建这个东西，它不会被传呼，它不会在第四十个雷同变更时感到疲惫。于是那个人会悄悄丢弃的提案，被完整地端了上来，附着自信的推理，站在它和 backlog 之间的，只剩有没有人说不。

作者想起几周前写过自己 agent 舰队长出一条十四车道的 CI 流水线，每条检查都由一起真实事故正当化。当时他把那读成一个关于谨慎的故事——其实那是一个关于生产的故事：**agent 不是在谨慎，agent 是在高产**，谨慎只是高产工作碰巧呈现的形状。同一个舰队最近又给了一个更干净的版本：一个副业项目里的边角情况，agent 可能留下指向空值的记录，受影响的只有作者自己。它花掉数小时 agent 时间、写了三份决策记录、读了一遍生产数据，最后作者看了一眼，说出了那句显而易见的话：这是过度工程，而且毫不务实。正确的答案是关掉它，真咬人再修。bug 没伤害任何人，倒是有几个小时被花在了修复它上。

这就是小规模的同一件事：**循环里没有任何东西在问「这项工作该不该存在」。** agent 的职责是解决被交给它的问题，而它做到了；判断问题值不值得解决从来不是它的职责——也从来不是其他任何人的职责，因为换成人，这道判断会不假思索地自动发生。

标准里有句话，作者一周比一周更喜欢：**分歧就是工作（Disagreement is the work）**。原本是为签收写的，但放在方案阶段更真——那是「说不」的成本是一场对话、而非一次重写的最后时点。

## 我们正在做的调整

处方并不复杂，作者还有点不好意思：上了线才看清它。

**人的判断左移，而且必须有人为「左移真的发生了」负责。** 工程师的注意力应该先落在方案而不是 diff 上：读一份提案设计、问一句「它是否与问题成比例」，是十分钟能干完的事；评审这份提案最终变成的代码是两天的事，而且到那时，沉没成本会替「合并」辩护。

更难的部分在于：方案阶段已经悄悄变成了最容易放行的一关。agent 展示一份附带推理的设计，推理连贯，批准它感觉像走个形式而不是做一个决定——这和你顺手批准信任之人的 PR 是同一个反射，只是这次用在了还没赢得信任的东西上。标准说人类保持问责，这必须意味着**对方案阶段的判断负责**，而不只是给走到终点的东西签字：如果一个没人需要的独立服务上线了，在设计评审时点头的人要认账——而且他必须在点头之前就知道自己要认这个账。

**我们更少地信任 agent 的提案了——具体说，不再信任它们的自信。** 坚持要独立服务的那个 agent 没有丝毫犹豫，而从外部看，自信的提案和错误的提案无法区分，所以自信不携带任何信息，必须在方案阶段把它折价到零。

两个问题替他们干掉了大部分活：第一，**如果这东西出错，受害的是用户还是我们自己？** 如果是我们，这项工作就是个「纸切伤」，多半不配拥有永久性的结构。第二，**提议的这条检查，是在保护用户免于缺陷，还是在规范 agent 的行为？** 如果是后者，它应该待在 agent 自己的循环里，而不是待在每一个变更都必须经过的大路上。把这两个问题应用到舰队上，一个下午就移掉了大半条流水线。

他们还在「教」agent 少提案：更小的方案、更短的文档、先给简单选项、精致选项扣住等简单方案失败再拿出。已经有效果了。

## 为什么它不会完全持久

作者之前写过：对 agent 的教练会衰减——它进入上下文的那天最强，随上下文增长、模型更替、工具漂移而减弱。这轮教练没有理由例外。一段时间内 agent 会提案更少；然后漂移开始，而且漂移的初次亮相不是更差的提案，而是**稍微长一点的提案**——稍微更周全一点，每一个都更难反驳一点。

所以教练不是修复。**方案阶段上的判断才是修复**，教练只是让这个判断在一段时间内变得便宜。等教练衰减殆尽，判断必须仍然在场——由一个人持有，在唯一一个「说不」只需要一场对话的阶段上。

进两步，退一步。他原本指望这套流程缓解队列。它确实缓解了——方式是让他看清：队列是一条「从来没人一直在做的决定」的下游。

# 《The PR bottleneck is a symptom》的发芽报告

## 材料核心

作者团队给「人与 agent 协作」立了五阶段流程，预期第一个暴露的问题是评审队列——agent 产出超过评审容量。流程实际暴露的更深一层是：agent 提出的工作常常超过问题本身的需要（独立授权服务、过度工程的三份决策记录），而这些提案在「方案阶段」本应被否掉。人会不假思索地在脑内自我把关，因为提出者就是承担者；agent 不承担任何成本，于是本该被悄悄丢弃的提案被完整端上桌。处方：人的判断左移到方案阶段、自信折价到零、两个过滤问题（伤害落谁/检查为谁服务）、教练 agent 少提案——但教练会衰减，判断必须由人常驻在唯一一个「说不」只花一场对话的时点。

## 发芽 01：产出廉价之后，判断「该不该做」成了稀缺资源

### 种子

循环里没有任何东西在问「这项工作该不该存在」——agent 的职责是解决被交给它的问题，判断问题值不值得解决从来不是它的职责，「也从来不是其他任何人的职责，因为人会不假思索地决定」。

### 故事

文章的两个案例都指向同一缺口：独立授权服务的提案每一环都合理（同步、对账、漂移检查各自成立），十四车道 CI 流水线每条检查都有真实事故背书——但「整体是否与问题成比例」没有人答。前者的成本是几周从未建造的工程，后者是几小时 agent 时间加三份决策记录去修一个没伤害任何人的 bug。

### Aha 瞬间

自动化把「做」的成本打到接近零，同时也把「不做」的成本从隐性变成显性——过去被人的本能免费挡掉的判断，现在必须有人显式地付费上岗。瓶颈从来不是产能，是没人认领的那道判断工序。

## 发芽 02：成本在谁身上，判断就在谁脑内

### 种子

人的过度工程大多死在自己脑子里——因为出主意的人就是扛活的人：写同步的是他，own 对账的是他，被传呼的还是他。这个前景在提案出口之前就把它编辑了一遍。

### 故事

agent 之所以把「人悄悄丢弃的提案」完整端上来，文章给了一个结构性解释：它不以任何让它付出代价的方式承担后果——不被传呼、不会疲惫、不在第四十个雷同变更时厌倦。于是唯一剩下的屏障是「有没有人说不」，而说不的最佳位置是方案阶段：那里否决的成本是一场对话，到了评审阶段就变成一次重写加沉没成本的辩护。

### Aha 瞬间

评估任何提案的质量时，先看提案者与承担者是不是同一个「身体」——当提案权与承担权分离，脑内自动把关就消失了，必须用制度把这道把关重新造出来，并且造在成本最低的时点上。

## 发芽 03：自信不携带信息——两种从外部无法区分的东西都不能信

### 种子

坚持要独立服务的 agent 没有丝毫犹豫，而自信的提案和错误的提案从外部无法区分——「所以自信不携带任何信息，必须在方案阶段把它折价到零」。

### 故事

文章把它落成可操作的过滤：教练 agent 少提案、先给简单选项；对提案附加的检查问两个问题——伤害落在用户还是我们自己（我们＝纸切伤，不配永久结构）、检查是保护用户还是规范 agent 行为（后者放进 agent 自己的循环）。一个下午，这两个问题移掉了大半条流水线。而作者清醒地补了后半句：这些教练会衰减，漂移的初次亮相不是更差的提案，而是稍长、稍周全、更难反驳的提案。

### Aha 瞬间

语气与结果独立，是协作 AI 时代的新常识：流畅、完整、笃定的表达里不含正确性的证据。凡是「从外部无法区分好坏」的信号，在决策里就该按零计——真正的判据要另找，比如「伤害落谁」和「这道检查到底在防什么」。
