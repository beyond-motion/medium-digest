# 递归自我改进需要一个更好的实验

> 原文：[Recursive Self-Improvement Needs a Better Experiment](https://medium.com/@SebastianMateusP/recursive-self-improvement-needs-a-better-experiment-e78c0cb1c245) — Sebastian Mateus

---

**更好的 agent，和更好的 agent 构建者，是两个不同的结果。**

想象一个机器人改进自己，然后改进它「改进自己」的能力。很酷。现在想象它的全部评估是一张往上走的图。稍微没那么酷了。

递归自我改进（RSI）值得一个比「最终 agent 得分更高了吗」更难的问题。我们还需要问：**产生改进的那个流程，本身变得更有效了吗？**

2026 年 10 月的一篇 preprint，《Auditing the Product, Not the Recursion》，把这两个主张分开了。在 26 项声称「改进流程变得更好」的研究中，作者们找出**只有 4 项在相同的起始工件、匹配的预算下，比较了较早与较晚的改进流程**。这是关于该审计的搜索范围与编码规则的发现，不是对全部 AI 研究的普查。

## 为什么起点很重要

先看审计发现了什么、再看为什么起点是关键变量。

假设第二版继承了一个更好的代码库、一份有用的记忆、和双倍的算力。它的最终答案可以改善——**即使它的编辑策略变差了。我们改了三个配料，却把功劳记给厨师的顿悟。**

## 我会用的实验模式

在同一份初始工件上、以相同的评估调用预算、跨多个随机种子，比较两个改进器。**把最终测试与用于挑选编辑的反馈分开保存。**

下面的 Python 例子用合成的搜索策略来说明比较结构；它不测量任何真实的 agent，也不建立 RSI：

```python
from random import Random
from statistics import mean

def improve(start, budget, seed, step):
    rng = Random(seed)
    current = start
    for _ in range(budget):
        proposal = current + rng.uniform(-step, step)
        if abs(proposal - 3) < abs(current - 3):
            current = proposal
    return current

gains = []
for seed in range(30):
    old = improve(0.0, 12, seed, step=0.5)
    new = improve(0.0, 12, seed, step=1.0)
    gains.append(abs(old - 3) - abs(new - 3))

print('Mean paired gain:', round(mean(gains), 3))
print('Runs favoring new:', sum(g > 0 for g in gains), '/', len(gains))
```

## 有用的统计单位：配对差值

这里有用的统计单位是**配对差值（paired difference）**：两个流程面对同一个起始问题、同一份预算。只有正的平均值还不够——在支撑一个一般性结论之前，你还需要不确定度估计、更宽的起始状态分布、以及一次独立的最终评估。这个玩具例子里反复出现的同一个目标，使它**故意不适合**作为泛化能力的证据。

## 真正值得研究的东西是存在的

## 真正值得研究的东西是存在的

Darwin Gödel Machine 修改 agent 的代码、并在编程任务上评估候选者。那是一个具体的实验系统——有明确的搜索空间与评估设定。它证明了「自我修改的改进器」可以从叙事变成被测量的对象。

让这些系统可度量，是让 RSI 讨论回到科学地面的前提。我的兴趣是让这些系统可度量：**保存每一个被提出的改动、统计被拒绝的候选数、核算评估器的成本、重跑整个循环。**再试一个等预算的基线——单纯搜索更多、但不更新改进器的那一个。

如果更新过的流程赢了那场比较，我们学到的就比「优化找到了一个更好的检查点」有意思得多。**我们得到的是关于优化器本身的证据。**

机器人可以保留它的戏剧性登场；实验需要对照组。

# 《Recursive Self-Improvement Needs a Better Experiment》的发芽报告

## 材料核心

RSI 评估的混淆变量拆解：「更好的 agent」≠「更好的 agent 构建者」——只看最终得分的一张上升曲线，无法区分「改进流程变强」与「投入变多」。2026-10 preprint《Auditing the Product, Not the Recursion》给出量化边界：26 项声称改进了改进流程的研究里，仅 4 项满足「相同起始工件+匹配预算下比较早晚流程」的严格条件（作者注明这是审计搜索框与编码规则的产物，非全体研究普查）。归因谬误示例：v2 继承更好代码库+有用记忆+双倍算力→结果改善被记给「编辑策略的顿悟」，实际是三个配料变了。处方：同一初始工件+相同评估调用预算+多种子比较两个改进器，最终测试与挑选编辑的反馈分离；统计单位是配对差值（Python 合成示例演示结构），正均值之外还需不确定度/更宽起始状态/独立终评；玩具的单一目标故意不构成泛化证据。正面样本：Darwin Gödel Machine（修改 agent 代码+编程任务评估）是具体可研究的系统。元度量清单：保存每个提案、统计被拒候选、核算评估器成本、重跑全循环、加等预算「只搜索更多不更新改进器」基线。金句：「机器人可以保留戏剧性登场；实验需要对照组。」

## 发芽 01：「改了三个配料，却把功劳记给厨师的顿悟」——RSI 归因的基本谬误

### 种子

v2 继承更好代码库、有用记忆、双倍算力，最终答案改善——即使编辑策略变差。「我们改了三个配料，却把功劳记给厨师的顿悟。」

### 故事

这是控制变量失效的经典形态：递归系统的每一代都继承了上一代的全部遗产（代码、记忆、算力、甚至评估器的改进），于是「产出提升」是遗产复利与策略改进的混合物。26 项研究只有 4 项分离干净，说明这个谬误是领域级的默认行为而非个别疏忽——因为分离的代价高昂（相同起始工件意味着放弃真实演进的叙事、匹配预算意味着烧真金白银跑对照）。preprint 的贡献是把「哪些研究过关」做成了可审计的清单。

### Aha 瞬间

**递归系统的每一代产物都是「策略 × 遗产」的乘积——只看乘积的上升，你永远不知道乘数有没有变大；RSI 的证据标准不是「第二代比第一代好」，而是「同样的遗产，新一代策略能把同一块料雕得更好」。**

## 发芽 02：配对差值与等预算基线——给「自我改进」装上对照组

### 种子

实验模式：同一初始工件、相同评估调用预算、多种子、配对差值；外加一个等预算基线——「单纯搜索更多、但不更新改进器」的那一个。金句：「机器人可以保留它的戏剧性登场；实验需要对照组。」

### 故事

配对差值（同种子同起点同预算下两流程结果之差）把噪声从信号里剥出来：种子方差被差分吸收，剩下的才是流程差异。等预算基线则是最锋利的一刀：如果「不改进改进器、只是搜得更狠」就能达到同样的提升，那么改进器更新的价值为零——大量 RSI 叙事在这一关就会现形，因为它们的收益本质上来自更多算力与更多评估调用。作者列的元度量（保存每个提案/统计被拒候选/核算评估器成本）进一步把「改进」从结果叙事变成过程遥测。

### Aha 瞬间

**自我改进主张的最小检验是「与一个傻但诚实的等预算基线比」——如果优化器的「顿悟」打平了纯暴力搜索，那么所谓递归只是算力换了件马甲；对照组的缺席，是这一领域戏剧性与科学性之间的全部距离。**

## 发芽 03：从单篇审计到领域规约——「只有 4 项过关」的元科学意义

### 种子

26 项声称改进流程的研究只有 4 项满足严格条件——作者谨慎注明这是审计搜索框与编码规则的结果，不是全体研究的普查。

### 故事

这个数字的正确读法不是「22 项都是坏的」，而是「按这个标准，可审计的 RSI 证据极其稀缺」——标准本身（相同起始工件/匹配预算/最终测试与反馈分离）构成了一个领域可以采纳的规约。这与本篇姊妹篇（安全指标需要与产出同测）合起来是同一个科学纪律的两面：单边指标与无对照叙事，是 agent 评估里最常见的两种自欺。玩具示例的诚实处理（「故意不适合作为泛化证据」）同样是示范：作者连自己的例子都不允许越界解释。

### Aha 瞬间

**「只有 4 项过关」不是对研究的否定，是一份领域规约的提案——当一个领域的证据稀缺到可以用一页纸的清单数完，最先采纳这份清单的人，将拥有其他人没有的东西：可比较的结果。**
