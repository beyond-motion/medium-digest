# 泄出的权重：AI 逃出 API 的那一年

> 原文：[The Weights That Got Out: The Year AI Escaped the API](https://medium.com/@cdcore/the-weights-that-got-out-the-year-ai-escaped-the-api-194eb8653fa5)

---

*How We Got Here：第 15 集（约 26 集）。我们一次一个贡献，走完 AI 的时间线。*

## 关掉 Wi-Fi，它还能用

今天，装好 Ollama 之后，你用一条命令就能试本地推理：`ollama run llama3`。第一次运行会下载模型，等它就绪，你让它解释一个 bug 或者起草一封邮件——它的回答和你惯用的聊天工具很像。区别在于：这次干活的模型在你自己的机器上。

关掉 Wi-Fi。它还能用。

文件就在你的 SSD 里，你的电脑拥有生成答案所需的一切。你不用把每个 prompt 发去某家公司的服务器，也不用为返回的每个 token 付费。

2023 年初，Meta 向通过审核的研究者发布了一个强语言模型。大约一周后，有人通过种子网络把它的权重散了出去。很快人们开始琢磨怎么在自己已有的硬件上跑它——以及一旦能跑，怎么改它。

对我关心的那类研究而言，第二件事和第一件同样要紧。能向模型提问只走得到这里；有时你需要把它打开，调查它为什么这样回答。

## 上集回顾：封闭模型的世界

第 14 集讲了 Constitutional AI 和 Anthropic 的 Claude：人类反馈能教模型哪种回答更受欢迎，但需要大量人打分，而且总得有人决定「好」的标准。Anthropic 写下一组成文原则——宪法——用它让模型批评并修订自己的回答。价值观变成了可以阅读和讨论的东西，哪怕模型本身还锁在公司的服务器上。

访问 GPT-3、GPT-4 和 Claude 意味着使用一项服务：文本进、答案出。你不能下载这些模型自己检查或修改。

别的研究组已经在解决这个问题。2022 年 5 月，Meta 宣布 OPT-175B，随模型家族一起发布了训练代码和实验日志；访问最大权重需要申请和一份非商业研究许可。7 月的后续报告：收到超过 4,500 份申请，向 49 个国家的 668 个实体放行——仍然有人在审申请。同年 7 月，BigScience 协作发布了 BLOOM：1760 亿参数、覆盖 46 种自然语言和 13 种编程语言、权重可下载但许可证限制了某些用途。

还有「放哪」的问题。BLOOM 的公告指引没有八张 A100 的人去用托管 API。你可以有下载模型的许可，却仍需要别人的服务器才能用上它。**Llama 到来时，研究者们已经在打开通道，但硬件账单依然悬着。**

## 被训练出来的数字

这一路我们都在说「权重（weights）」。神经网络产出的语言底下，是数百万到数十亿个数字。每个权重决定网络的一部分对另一部分的影响力——把它们想成旋钮：训练开始时旋钮是随机设置，模型处理文本、出错，反向传播（我们在第 3 集见过）告诉训练过程该怎么拧。在海量文本上重复这个过程——通常在几千张 GPU 上跑几周——网络就变得很会预测下一个词。

训练出的数值被存进文件。那就是权重。代码描述网络、执行计算；权重携带训练中学到的东西。跑那个特定的模型，两者都要有。

值得强调：**权重文件不是训练库的可搜索副本。**那些数字编码的是跨样本学到的模式，不是一张能查出每个答案出处的表。持有它们给你的是访问计算的能力，理解某个具体计算的含义仍要下功夫。

还要区分训练和推理——推理是运行训练好的模型产出答案。普通推理时模型只用既有权重，不会因为你打字就重新训练。这就是为什么实验室可以重金训练一次，然后分发文件让别人使用而不必重复训练。

封闭模型呢？你可以有相似网络的代码，却仍然缺那件花大价钱才生产出来的东西。OpenAI 留着自己的权重，Anthropic 也是。API 给你结果，不给你文件。

## 一场没守住的研究发布

2023 年 2 月，Meta 的 FAIR 实验室发布 Llama：四个语言模型，从 70 亿到 650 亿参数，以尺寸论异常能打——最大的那个能和比它大几倍的模型过招。

Llama 论文解释了这背后的取舍：作者要的是**反复运行起来经济的模型**，哪怕生产它们需要更多训练。当最终用户要一次又一次为推理付费时，「更小的模型、更久的训练」是一笔合算的交易。7B 和 13B 各自在 1 万亿 token 上训练；作者报告 13B 在他们的大多数基准上超过了 GPT-3 的 175B 模型。这个比较说的是特定测试上的预训练模型——它没有证明 13B 的下载版在对话上等于 ChatGPT，但它给了研究者认真对待一个小得多的模型的理由。

论文也记录了数据配方：以 CommonCrawl 和 C4 网页文本为主，混入 GitHub、Wikipedia、书籍、arXiv、Stack Exchange。成分大类有文档，但读者拿到的权重并不附带那份精确处理过的训练语料。

发布是受控的：研究者申请，Meta 在非商业研究许可下提供权重。你下载得到的前提是申请被批。Meta 当时的首席 AI 科学家是 Yann LeCun——第 4 集里那位 1989 年造出读手写邮编的卷积网络、在业内多数人已放弃神经网络时的坚持者。三十四年后，他的实验室在把训练好的语言模型交到研究者手里。

发布后约一周，权重以种子形式流传开来。链接出现在 Meta 自己 GitHub 的一个 pull request 里，也出现在 4chan，署名「llamanon」。种子网络把文件分布在所有下载者之间——你收到碎片的同时可以把碎片分享给别人。一旦足够多的人有了副本，删原始链接对阻止传播收效甚微。Meta 申请下架，GitHub 删了一个仓库，但副本已在流传。**从未走过申请流程的人，现在也能下载这个模型了。**

## 让它塞得进去

文件很大，对坐在笔记本前的人，跑起来仍是障碍。3 月，Georgi Gerganov 发布 llama.cpp：一个用 C/C++ 写的、能在 CPU 上运行 Llama 的实现。你不需要数据中心 GPU。量化（quantization）技术让较小的模型版本在普通机器上变得可行。

项目 README 的早期版本记录着这实现当时多实验性：Gerganov 只测过 7B；README 里有关于一个产生乱码输出的 bug 的提示，他还不确定量化对质量影响多大。代码面向 Apple silicon 的 CPU，用 Arm Neon 和 Apple 的 Accelerate 框架。示例运行的 prompt 是建个网站——它输出了一份编号清单，然后开始绕着网站和托管做重复解释。毛边肉眼可见。**成就是让计算在本地跑起来了；打磨成一个体面的助手还需更多工作。**

每个权重存 16 或 32 位给你很高的精度，但数十亿个这样的数字占很多内存——你还没提问，模型可能已经超出笔记本的容量。量化用更少的位（常见 4 位）存这些数字：损失精度，有时伤回答；但如果代价足够小，你就得到一个塞得进小内存的可用模型。这和把照片压成 JPEG 是同一种交易——丢一些信息换更小的体积，尽量保住你在乎的细节。问题变成：在模型回答坏到影响你的任务之前，你可以放弃多少数值精度。

粗算一下值得：70 亿个数，每个 16 位，约 140 亿字节（十进制 14 GB）。每位 4 个比特时，原始权重存储降到约 3.5 GB。实际文件还需要描述量化方式的信息，各实现也未必对每部分用同一精度——3.5 GB 是个有用的估计，不是对最终下载体积的承诺。

运行还需要工作内存。一个原因是 key-value cache：为前面的 token 存下的注意力计算，省得每生成一个新 token 就重算。标准全注意力模型里，缓存随对话增长。**放得进磁盘的文件，一旦要处理长 prompt，内存可能仍然吃紧。**减权重解决了问题的大头，但对话长度也有分量。

本地 CPU 推理让泄出的权重对大得多的群体有了用处。几周之内，人们可以在自己的电脑上离线运行一个能干的语言模型——而且 demo 跑通之后还能继续实验，因为模型本身在他们手里。Hugging Face 成为分发中心：人们把 Llama 微调成编程、医疗文本、其他语言版本，然后分享修改后的模型。数千个社区变体接踵而至。

微调的意思是：拿着训练好的权重，在更小的数据上继续训练。你从模型已学的东西出发——这让「改造」远比从零训练一个相当的模型容易触达。

## 下载的还不是助手

最初的 Llama 是预训练文本生成器，「听指令」的行为需要额外的工作。这就是第 13 集那个区分的实用之处：一个擅长续写文本的模型，未必可靠地表现得像你提问时期待的那个助手。

3 月 13 日，斯坦福的研究者推出 Alpaca：用 OpenAI text-davinci-003 生成的 52,000 条指令遵循样本微调 Llama 7B。他们报告生成数据花了不到 500 美元，微调算力不到 100 美元。注意这笔估算只覆盖「改造已有模型」——Meta 的预训练成本不在预算内。而且 Alpaca 的初始调优仍用了 8 张 80GB A100 跑 3 小时——**小小的美元数字反映的是短暂租用大硬件，不是全在笔记本上完成。**斯坦福公开了数据和训练配方，同时警告模型会幻觉、不宜直接部署；项目限研究用途。吸引力在于：另一个研究组可以检视并复现「改造」这一步，而不必先供着一个基础模型。

同月稍晚，Vicuna 换了素材来源：用户通过 ShareGPT 分享的约 70,000 段 ChatGPT 对话。开发者把 Llama 13B 改造成多轮对话模型，报告用折扣云竞价实例花了约 300 美元。发布公告宣称达到 ChatGPT 质量的 90% 以上——但团队自己的脚注承认这个评估不科学：GPT-4 对 80 个问题的答案做了裁判。**那是一种早期的比较方式，不是「ChatGPT 能力的 90%」的度量。**

## 改更少的数字

运行权重和更新权重，内存需求不同。全量微调还需要放梯度和优化器训练状态的空间——推理放得下的模型，训练时未必放得下。

一个有用的技术早已存在：微软研究者 2021 年提出的 LoRA（Low-Rank Adaptation）。它冻结预训练权重，通过加到网络部分位置的小得多的矩阵来学习改动——不存储、不训练每个权重的完整独立副本，只学一个紧凑的调整量。

矩阵是矩形的数字阵列。粗略的例子：一个 4096×4096 的权重矩阵含超过 1600 万个值；一个秩 8 的 LoRA 更新可以用一个 4096×8 加一个 8×4096 的矩阵表示——合计 65,536 个值。两个小矩阵相乘，产出一个与原矩阵同尺寸的更新。原矩阵仍在；训练调整的是那两个小的——这就是它省训练内存又不让底模消失的原因。

2023 年 5 月，QLoRA 把这个思路与「冻结模型按 4 位精度存储」结合：研究者在一张 48GB 内存的 GPU 上微调了 650 亿参数的模型。基座权重按 4 位存储，训练调整的是 LoRA 参数；计算时会反量化——这不等于每一步训练计算都只用 4 个比特。

## Meta 接下来放了什么

2023 年 7 月，Meta 发布 Llama 2，有意让权重可用于研究和商业。之前拿第一版做实验的人，现在有了一个可以在上面盖生意的模型（受 Meta 许可约束）。Meta 同时发布了聊天调优版。Llama 2 报告描述了监督微调加人类反馈强化学习——与系列前面讲指令跟随模型时相同的大序列。团队收集了超过一百万条人类对模型回答的偏好比较来训练奖励模型——那是偏好判断，不是一百万条手写的理想答案。

发布包括 7B、13B、70B。上下文窗口从 Llama 1 的 2,048 翻倍到 4,096——模型单次上下文里有更多文本可用。这个上限覆盖模型能注意到的序列，**不是**「记住用户说过的一切」的成长式记忆。

到 7 月，从 Meta 下载的人可以选一个预训练起点做自己的研究，或选一个已为对话调好的版本。模型尺寸不再告诉你该期待什么行为——你下载的是哪个版本开始变得要紧。

许可证对月活超过 7 亿的公司要求特殊许可，并禁止用 Llama 素材或输出去改进 Llama 2 家族之外的其他大模型。开源促进会（OSI）反对把它叫作开源。人们此前对第一版 Llama 也用过这个称呼——你可以下载、自己运行、修改、分享你的产物，看起来足够像和开源软件打交道，标签就贴上了。

但这里缠着两个独立的问题。一是**发布包含了什么**：Llama 权重不附带完整训练数据和复现模型所需的全部代码与流程。二是**许可允许什么**：下载文件并不能取消限制。**开放权重（open weights）描述的是你实际收到的训练参数**——它们让你运行模型、在自己的数据上继续训练；商用、再分发、用其输出改进别的模型，仍取决于许可证。

## 研究者拿它能干什么

API 让你研究模型产出的答案；有了权重，研究者还能检视内部、做 API 不开放的实验。当你想理解模型为什么这样表现、而不只是测对错频率时，这件事要紧。数十亿个数字依然难解读，但对独立研究者，下载模型让一种仅靠聊天框无法支撑的研究成为可能。

就算你从不检视一个权重，也有实际的理由在乎这件事。本地跑模型，你的 prompt 可以不离开你的机器。对处理敏感数据的实验室、医院、律所，避开第三方推理服务能让一个项目从不可能变可能；对单纯不想把文字发给别人的个人，也一样。留下模型还意味着留住一个特定版本——不会被厂商在你脚下悄悄换掉——并在硬件与许可允许时用自己的数据改造它。成本转移到你这边：没有按 token 计费的 API 商，但机器和运维归你。而没有完整训练数据与流程，你仍然无法复现原始训练、无法完全审计里面进了什么。

2024 年，Allen Institute for AI 的 OLMo 发布把这条线推到了头：附训练语料、训练代码、日志和数百个中间检查点（checkpoint 是训练某阶段保存的一组权重）。研究者可以用中间文件比较模型发展中的不同时点，配套的数据顺序工具让他们检视每一步看过哪些训练材料——在最终检查点之前就有证据研究行为如何形成。重复或扩展实验仍需要算力，但设计实验所需的证据多了大半。

## 分享它时你交出的控制权

上一集花了很多篇幅讲教模型拒绝有害请求。**分享权重让这份努力复杂化**：能微调模型的人，也能削弱或移除它的创造者教进去的行为——包括安全训练。让研究者能把模型改造去做有用的事的同一种访问权，也让另一个人能把它训练得服从它从前拒绝的请求。

这在 2023 年晚些时候成为实证发现：研究微调与安全的研究者发现，改造会损害 Llama 2-Chat 和 GPT-3.5 Turbo 的安全行为——有些退化甚至出现在普通的、非对抗性的微调数据集上。组织可以让模型在选定任务上更好，同时削弱它以为会原样保留的行为。GPT-3.5 的实验对论点同样要紧：它们用的是托管微调服务——**漏洞不是下载权重的独有属性**。让任何人能改变模型行为，本身就是一个安全问题，哪怕文件仍在厂商手里。开放权重让集中执行更难，但私藏权重也并不能保证每一次被许可的改造都会保留原本的防护。

通过 API 服务的实验室可以控制运行版本、限制访问；一旦别人有了权重副本，实验室对他们拿副本做什么，就无法施加同样的控制。删一个下载链接，取不回文件。这让我不安——即便我希望研究者拥有这种访问。我无法靠指着一堆有用的实验让安全问题消失；我也不想让一小撮公司以他们定的价格，决定谁有资格做实验。

权力扩散还有另一条边界：下载并改造一个模型，远比从零造一个同等能力的模型便宜。前沿训练仍集中在付得起数千万美元算力、巨型数据集、以及知道怎么把训练跑起来的那些实验室。

## 回到你的笔记本

Ollama、LM Studio、llama.cpp 这类工具让本地推理容易到可以在「怎么搭这个东西」的决策里顺手选它。Llama 的发布与围绕它的工作，让它成为更多人买得起的选项。泄漏是这段历史的一部分——和那些不那么戏剧性、却让文件真正可用的工程工作一起。

当实验室管一个模型叫「开放」，我想知道的是我实际能拿它做什么。有文件，意味着我可以试着在我控制的硬件上跑它；我仍要读许可证才知道能改什么、分享什么；我仍要看实验室还发布了什么，才知道训练过程有多少可检视。**文件可以在我手里，工作所需的其余部分仍然缺着。**

下周二：给模型一本打开的书。你磁盘上的模型并不知道同事今早发你的报告里写了什么。它的训练知识来自它学过的数据；你的私人文件不会因为它跑在你电脑上就出现在它的权重里。我们将看检索增强生成（RAG）：找到相关文档、作为上下文供给模型——大量「和你的文档聊天」工具背后的方法，一种不重训练就给模型新鲜或私有信息的途径。

如果你有队友正在本地模型和 API 之间摇摆，把这集转给他。系列在 Medium 可追、Substack 可订阅：周二出系列集，周三周四写我当周在造什么、在看什么。

# 《The Weights That Got Out》的发芽报告

## 材料核心

这一集讲的是 2023 年「AI 逃出 API」的连锁事件：Meta 以受控研究许可发布 Llama，一周内权重经种子网络泄漏；llama.cpp 与量化让它在普通 CPU 上跑起来；Alpaca 用 500 美元加上指令数据教会它当助手；LoRA/QLoRA 把微调门槛压到一张卡；Llama 2 让「开放权重」合法商用——以及随之而来的安全复杂化：能微调就能削弱安全训练。

## 发芽 01：「泄漏」只是引子，可用性是工程喂出来的

### 种子

权重泄出的一周内就能下载，但真正让它「有用」的，是后续一整串不起眼的工程。

### 故事

文章的线索摆得很清楚：种子泄漏只解决「拿到」；llama.cpp 解决「跑得动」（CPU + 量化，16 位的 14 GB 压到 4 位的约 3.5 GB）；Alpaca 解决「像助手」（52K 指令样本微调，不到 600 美元）；LoRA/QLoRA 解决「改得起」（秩 8 的调整量只需 65,536 个值去更新一个 1600 万值的矩阵；65B 模型塞进一张 48GB 卡）。

### Aha 瞬间

历史的转折点常被记成单一事件（「Llama 泄漏了」），但让转折真正发生的是一列互补的降门槛工程——获取、运行、对话化、改造，每一环都少不得。评估一个「泄出/开放」事件的影响时，该问的是配套可用性栈的成熟度，而不是泄漏本身。

## 发芽 02：「开放」是个光谱，「开源」是个被滥用 stole 的词

### 种子

开放权重描述你实际收到的训练参数；开源则承诺更多——而 Llama 两者之间的差距被标签糊住了。

### 故事

文章把两个被缠在一起的问题拆开：内容上，Llama 权重不附训练语料与完整流程，你拿到的是计算能力而非可复现性（直到 2024 年 OLMo 附上语料、代码、日志和数百个中间检查点，才把「可审计的训练过程」做成现实）；许可上，700M MAU 门槛与「不得用输出改进别家模型」的条款让 OSI 出面反对「开源」之称。

### Aha 瞬间

下次看到「开放」先拆成三问：拿到了什么（权重？语料？代码？）、能做什么（许可边界）、能审计什么（复现与检查点）。文件在手不等于工作所需的一切在手——这句话对所有「开放」宣称都是通用的尽调清单。

## 发芽 03：可改造性与安全性的同源困境

### 种子

让研究者能把模型改造去做有用的事的同一种访问权，也让任何人能把它训练得服从它从前拒绝的请求。

### 故事

2023 年的实证发现给了这一担忧以数据：普通的、非对抗性的微调数据集就能削弱 Llama 2-Chat 与 GPT-3.5 Turbo 的安全行为——组织让模型在选定任务上更好时，可能悄悄磨掉它以为还在的防护。而 GPT-3.5 的实验用的是托管微调服务，说明漏洞不随权重转移：能改行为本身就是安全暴露，与文件在哪无关。

### Aha 瞬间

安全不是模型的属性，而是「模型+其使用环境」系统的属性：集中托管能控制版本与准入却防不住托管侧的微调滥用，开放权重可本地审计却防不住恶意改造。没有一种分发形态同时买断两端——真正的护栏只能建在「改造之后仍有可审计性」这一层，比如回流券式的改造登记与再评估。
