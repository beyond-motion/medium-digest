# 什么值得记住？记忆对每条消息做的最难决定

> 原文：[What's Worth Remembering? The Hardest Decision a Memory Makes on Every Message](https://medium.com/@omerfonder/whats-worth-remembering-the-hardest-decision-a-memory-makes-on-every-message-1f1e948439e0)

---

*这是一篇关于为组织构建记忆层的系列文章的第二篇。第一篇的论点是：存储不是记忆——区别在于行为。这一篇讲的是第一个行为：决定什么该留下。*

在上一篇文章里我主张：**你的 wiki 是存储，不是记忆；有意思的工作全部发生在「写下某样东西」和「需要把它找回来」之间。**这一次我想从那个「之间」的最开端讲起——比检索更早，比冲突检测更早，比任何你会称之为「智能」的东西都早。

记忆做出的第一个决定，也是最影响深远的那个，恰恰是没人谈论的那个：**这条东西到底该不该被记住？**

往一边做错，你的记忆就成了一份逐字稿——每一句「lgtm」、每一句「跑起来晚点了」、每一句「ok 我推上去了」都被永久保存，把真正重要的三句话淹没掉。往另一边做错，你扔掉的可能是那次站会上唯一一个六个月后还会被需要的决定。下游的一切行为——检索、冲突检测、知识整合——全部继承这道门的输出质量。垃圾进了门，垃圾就会被检索，被拿来对账，被整合成更多垃圾。**这道门是承重墙。**

## 一个团队说的话大部分是噪音——而且是故意的

让一个 sprint 成为如此严苛的测试输入的原因在于：**它里面压倒性 majority 的内容本来就是「注定速朽」的。**这不是团队沟通的缺陷，这就是设计意图。「我周四前把迁移做完」在周二有用，到下周一就毫无意义。**状态本来就应该过期。**而信号——「我们决定了：迁移跑在网关层，不是每个服务各自跑」——是稀有的，它埋在噪音中间，而且措辞和噪音一样随意。

所以这道门不能保留一切（那是聊天记录，我们已经有聊天记录了），也不能保留最响亮或最新的东西（状态恰恰就是最响亮、最新的那类）。它必须识别一种**类型**的陈述——持久的那一类——无论它的措辞多么随便。

## 「持久」到底是什么意思

我定了一个可执行的定义：**持久知识（durable knowledge）是任何在被说出的那一刻之后仍然为真、且可复用的东西。**

具体来说，我们的 Cortex 只放行这几类进入知识库：

* **规则（Rules）**——「我们把重试上限设为 3」
* **约束（Constraints）**——「鉴权变更必须先过合规评审」
* **能力（Capabilities）**——「ingest 服务可以从任意 offset 重放」
* **依赖（Dependencies）**——「checkout 依赖 pricing 服务的可用性」
* **风险（Risks）**——「遗留解析器遇到非 UTF-8 输入会挂」
* **流程规则（Process rules）**——「release 分支每周四切」
* **定义（Definitions）**——某个任务或系统到底是什么

而它明确拒收：状态更新、日期、一切锚定在「今天」「昨天」上的东西、进行中的闲聊。这些进日报（daily log）——它们被记录，只是不被升级为**记忆**。**「被记录」和「被记住」的区分，就是全部设计。**

## 这道门怎么工作——以及它哪里脆弱

我会诚实地讲实现，因为诚实的版本比 impress 的版本更有用。

第一遍是**正则**。一组速朽模式（「今天」「昨天」「EOD 前」「跑起来晚点了」、现在进行时的进度动词）在花一分钱调 LLM 之前，先把明显的噪音廉价地筛掉。另一组持久信号往反方向加权。它快、免费，对响亮而明显的情形完全够用。

但它也是脆弱的，我想把脆弱的方式精确地展示出来，因为这一部分才区分得出真实设计和 demo：

* 它会**误伤（misfire）**。「我们等了那个 PR」会触发速朽过滤器——「等了」是过去式，听起来像状态——但它可能编码着一条真实的流程事实（「我们部署前总要等 PR」）。正则分辨不出来，因为区别在**意图**，不在词汇。
* 它会**漏掉（miss）**。「这是当前的政策」在人眼里一瞬间就是持久知识，但「当前（currently）」在模式匹配器眼里是时间信号，可能因此被滤掉。对人标记持久性的那个词，对正则标记的是速朽。

模式匹配作用于词语。持久性关于含义。这两者重叠到足以让正则成为一个有用的**第一道**过滤器，又分歧到足以让它不能是**唯一**一道。所以任何熬过正则的消息都会进 LLM，带着一个单一的、收窄的问题——这里有没有持久知识，有还是没有，有的话是什么——然后由 LLM 把幸存者规范化成统一的、政策式语言，免得「重试上限 3 次」和「重试最多三次」变成两条独立的记忆。

**正则存在的意义不是正确，是便宜。**昂贵的、正确的东西只运行在那一小撮「可能要紧」的消息上。

## 两件我做对了的事，和一件我会重做的事

两个我愿意跟任何人辩护的设计选择：

**来源（Provenance）。**每一条持久事实都存储它来源的那条消息的 id。这听起来像记账，直到第一次有人问「等等，系统是从哪儿得到这条的？」——而你可以精确地用原始消息回答。**一个不能被质询的记忆，是一个不能被信任的记忆，而信任就是这东西的全部价值主张。**大多数工具跳过这一点。这很罕见，而且值得。

**版本链，而不是覆盖。**当一条事实变了，旧版本不被删除——新版本记录自己**取代（supersede）**了旧的。知识在演化，而它如何演化的历史本身就是知识。「我们曾经把重试上限设为 5，现在是 3」比光秃秃的「3」有用得多：因为下一个提议 5 的人能看到 5 已经被试过了。

而我会重做的那件：持久类型是一个**固定的六七个枚举**。作为上线决策这是对的，作为长期居住这是错的。真实的组织有自己的本体论——硬件团队的持久类型不会是金融科技团队的那几类。把类别烤死在代码里，意味着每个团队都被迫用我的分类。正确的版本是让每个 workspace 定义自己的类型，在抽取时喂给 LLM 门。我建的时候就知道这一点；我还是上线了固定清单，因为**一个能工作的窄东西，胜过一个不存在的完美通用东西。但它是债，我把它叫作债。**

## 值得留下的那部分

这道门之所以重要，是因为**它是唯一一个运行在字面上的每一条消息上的行为，而下游的一切都信任它的输出。**检索只能浮出被留下的东西；冲突检测只能对被留下的东西对账；整合只能合并被留下的东西。这道门是记忆的免疫系统——和免疫系统一样，两种失败模式都很糟：太宽容，你被噪音淹没；太激进，你毁掉了你需要的东西。

存储没有这个问题，因为存储不做决定——它保留一切，把成本推给读者，在最坏的时机、以最贵的方式。

**选择记住什么，是让一个存储变成记忆的第一件事。**

（下一篇：当你决定记住「API Gateway 把重试上限设为 3」，系统怎么知道「the API Gateway」「the api gateway」和「API GW」是同一个东西——同时又不把「Auth」和「Author」搞混？实体消解，每张知识图谱都不性感的核心。）

# 《What's Worth Remembering? The Hardest Decision a Memory Makes on Every Message》的发芽报告

## 材料核心

这篇材料把「组织记忆」拆到最底层的那个决定上：每条消息进门时，要不要记住它。作者的论点是这道门是承重墙——检索、冲突检测、知识整合的质量全部继承它的输出，垃圾进门就会沿着整条管线繁殖成更多垃圾。围绕这道门，材料给出了一个完整的工程答案：持久知识的可执行定义（超越被说出的那一刻仍为真且可复用）、七类准入枚举与明确拒收清单、「被记录」与「被记住」的分离、正则做廉价第一遍加 LLM 做窄问题第二遍的双层门、来源 id 与版本链两个信任机制，以及一个被作者自己标记为债的妥协（固定类型清单）。全部落在一个区分上：存储保留一切、把成本推给读者；记忆选择记住什么——这是它成为记忆的第一件事。

## 发芽 01：噪音不是失败，是系统的默认设计

### 种子

材料对 sprint 的观察反直觉：压倒性多数的对话内容「本来就该速朽」——这不是沟通的缺陷，是设计意图。「我周四前做完迁移」在周二有用、下周一作废。状态本该过期。

### 故事

所以难点不是过滤失败，而是信号的三重伪装：它稀有、埋在噪音中间、而且措辞和噪音一样随意（「我们决定了迁移跑网关层」说得跟「我晚点跑起来」一个语气）。这道门不能按响亮度或新旧来选——最响最新的恰恰是状态。

### Aha 瞬间

一个系统的输入大部分是「注定作废」的，这不是脏数据，是正常运转的证据。真正的工程问题从来不是「怎么留住一切」，而是「怎么认出那百分之几不许过期的话」——哪怕它穿着和噪音一模一样的外衣。

## 发芽 02：词与义的缝隙，就是双层过滤器的存在理由

### 种子

材料对正则失败模式的解剖精确到词：「我们等了那个 PR」会误伤（过去式像状态，实为流程事实），「这是当前的政策」会漏掉（「当前」对人是持久信号、对正则是时间信号）。结论一句话：模式匹配作用于词，持久性关于含义。

### 故事

解法不是让第一层更聪明，而是给它换个任务：正则不是「为了正确」存在的，是「为了便宜」——它把昂贵的、正确的 LLM 判断挤到只跑在那一小撮可能要紧的消息上。LLM 那一层则只问一个收窄的问题，并顺手把同义表述规范化成统一语言，防止一条知识变成两条记忆。

### Aha 瞬间

当语义判断昂贵而词汇判断廉价，正确的架构不是二选一，是让便宜的那层当守门人、让贵的判断只花在值得的地方——过滤器的第一美德不是准，是让错误的成本结构变得可以承受。

## 发芽 03：能被质询，才配被信任

### 种子

材料给出的两个信任机制都很朴素：每条持久事实存来源消息的 id（Provenance），事实变更不覆盖旧版而是记录「取代」关系（版本链）。作者说大多数工具跳过这两点——「一个不能被质询的记忆，是一个不能被信任的记忆」。

### 故事

版本链的价值藏在那个具体场景里：下一个提议「把重试上限调回 5」的人，能看到「5 曾经被试过、后来改成 3」——知识演化史本身就是知识，抹掉历史的覆盖操作等于烧掉组织已经付过学费的教训。而作者对自己债务的坦白同样关键：固定七类枚举是「上线正确的决定、居住错误的决定」，硬件团队的持久类型不会是金融科技团队的。

### Aha 瞬间

信任不来自系统说「相信我」，来自每个结论都能带着它的出处和演化史来见你——而敢在发布时就给自己的妥协贴上「债」的标签，是这份信任能够成立的前提。
