# 从检索到状态：重新思考 AI agent 的长期记忆

> 原文：[From retrieval to state: rethinking long-term memory for AI agents](https://medium.com/@ruxiz2005/from-retrieval-to-state-rethinking-long-term-memory-for-ai-agents-4edfcc553ee0)

---

## 摘要：检索之外的真正难题

大多数 agent 记忆系统都从同一条熟悉的管线出发：存储过去的观察、嵌入向量化、语义检索相关记忆、回填进上下文。当问题只是「想起早先出现过的一个事实」时，这套流程工作得很好。但当过去包含同一个事实的多个版本、互相矛盾的陈述、取代早期偏好后续生效的决策、或跨会话演化的目标时，它就开始变得不可靠。

作者（Ruxi Zhang）在构建 TypedMem（一个类型化记忆系统）和 ReliAgent Bench（一个基准测试）时遇到了这个问题。在基准上，增加更多检索并不够——记忆系统还需要区分被记住信息的不同种类、对时间有效性做推理、并裁决「哪条被检索到的证据应该支配当前答案」。在一次迭代中，加入一个 resolver（裁决器）把过期记忆错误从 37% 降到了零，总体基准准确率从 33% 提升到 78%；此后，主导错误转移到了路由而非检索本身。

这改变了她对长期 agent 记忆的看法。核心问题不再只是**「哪段过去的文本是相关的？」**而是**「鉴于已经发生的一切，agent 现在应该相信什么？」**

## 检索是必要的，但检索不是记忆

考虑一段简单的历史：一月，Alice 偏好早晨开会；三月，Alice 开始早上送女儿上学；四月，Alice 要求把例行会议挪到 10:30 之后；九月，用户问：「我该什么时候安排与 Alice 的会议？」

向量搜索很可能正确地检索到「Alice 偏好早晨开会」。这条记忆在语义上是相关的——但它已经不足以回答问题。系统需要理解：后来的事件改变了早期偏好的操作性含义。**更多检索并不能修复这一点**，因为检索系统可能干脆把两条都返回。难点在下游：哪条陈述是当前有效的？后一条是取代了前一条，还是仅仅限定它？它是一次临时例外吗？一个隐式的决定能否推翻显式的旧偏好？随着记忆积累到数周或数月，这类区分会越来越重要。

## 记忆有不同的语义

第二个问题出现在「所有记忆都被表示为可互换的文本」时。看看这五句话：「我喜欢靠窗的座位」（偏好）、「我订了明天的 14A」（事件）、「我的航班被取消了」（历史事实）、「下次避开早上六点的航班」（决策）、「我通常和女儿一起旅行」（可能持久的个人上下文）。它们是不同种类的信息——把五条全部当成同一个无差别池子里的嵌入向量，等于丢掉了日后有用的信息。

EVENT（事件）是关于过去、永远为真的历史事实；STATE（状态）会被新状态覆盖（住在圣何塞→住在西雅图，新的胜出）；PREFERENCE（偏好）可能被取代或被限定（喜欢早晨→偏好 10:30 之后）；DECISION（决策）是显式替换（用 A 供应商→换 B）。**不同的记忆类型有不同的持久性与取代语义。** TypedMem 因此从一个不同的表示出发：记忆项携带语义，帮助决定它们应如何被检索与裁决。具体 schema 不如原则重要——一个事件、一个偏好、一个决策和一个变化中的状态，不应该服从同一套更新规则。

## 难的是历史，不是存储

基准工作让这一点更清楚。ReliAgent Bench 从相对简单的检索案例，扩展到包含长历史、矛盾、跨会话信息、隐式目标、混合记忆类型与隐式决策的案例。

一个代表型的失败不是「系统找不到相关记忆」，而更接近于：检索到了相关的旧偏好 ✓、相关的新决策 ✓、相关的中间事件 ✓——然后答案用错了 ✗。信息是可得的，记忆系统没能从中构造出正确的当前解释。这导向了一条把职责分开的管线：**query → router（路由）→ filters（过滤）→ vector search（向量检索）→ ranking（排序）→ resolver（裁决）→ 当前答案**。

resolver 尤其有揭示性：一次基准迭代中，过期记忆错误占失败的 37%；加入显式裁决逻辑后，这一类降到了零，总体准确率从 33% 移到 78%，而剩余的主导错误转向了路由。作者强调不必把这组数字读作「这个架构就是最终答案」——它们说明的是更有用的事：**一旦检索变得足够好，瓶颈就会从「找到记忆」转移到「正确解释记忆」。**

## 记忆应该表示变化

这导向一个不同的心智模型。不再把长期记忆看作「过去文本 → 向量数据库 → 相似文本」，而是看成**一串状态与状态之间的转换**：一个事件推动状态，一个决策替换它的一部分，新证据修正它，一次偏好更新限定它。对比可以写得非常直白——传统记忆是四散的 chunk（块），靠相似度搜索汇拢；面向状态的记忆是 S₁ ──事件──→ S₂ ──决策──→ S₃ ──更新──→ 现在。

## 有用的记忆系统应该能自我解释

如果系统回答「把会议安排在 10:30 之后」，理想情况下应该能重构出为什么：旧记忆「偏好早晨开会」→ 后来的约束「早上要送上学」→ 显式决策「例行会议挪到 10:30 后」→ 当前答案「10:30 之后安排」。

这不仅是可解释性的问题。它让我们能把被单一检索分数压扁成一团数字的失败区分开来：**检索失败**——相关证据从未被找到；**路由失败**——查询搜错了记忆的种类；**排序失败**——正确的证据被检索到但被埋没；**裁决失败**——冲突的证据被找到了但被错误解读；**表示失败**——记忆系统没有编码出裁决该案例所需的区分。这套分解让 TypedMem 的调试比「把记忆质量当成一个检索分数」有用得多。

## agent 到底应该记住什么？

这是作者认为 TypedMem 最终要回答的问题。全量存储很有吸引力，因为它避免了在写入时做出不可逆的决定；但无限存储并不解决记忆，它把难度转移给检索与裁决，同时增加无关上下文与矛盾。激进摘要则相反：它能高效压缩历史，也可能悄悄删掉日后重新解释某个事件所需的那个细节。

她在探索的设计位于两个极端之间：原始历史保持可作为证据获取，同时由一个更小的结构化记忆层维护「预期跨会话仍有用」的信息——持久事实、变化中的状态、偏好、决策、目标，以及它们更新之间的关系。由此得到的架构不像一个笔记本，更像一个持续更新的用户或环境模型。

## 下一步要度量什么

下一阶段应该超越聚合式的基准准确率。一个有用的长期记忆系统至少应回答四个可测的问题：**时间正确性**——系统是否用「请求时点有效的信息」回答，而不只是检索语义相似的陈述；**矛盾解决**——后来的证据、显式纠正与取代性决策是否被一致处理；**因果可追溯性**——一个答案能否追溯到产生当前状态的那串记忆与更新；**长程稳定性**——当历史跨许多会话增长时，以上性质是否仍然成立。

这也是她不想让 TypedMem 变成领域特定 schema 集合的原因：一个有用的抽象应该横跨个人记忆、育儿记录、宠物记录、读书笔记和 agent 执行日志，而不需要为每个应用定制一套本体论。目标不是预知用户在乎的每一个事实类别，而是表示出足够的关于**时间、类型、变化与证据**的结构，让系统能推理「什么仍然为真」。

## 结论

她从 TypedMem 出发时想的主要是检索：当 agent 需要时，如何从漫长历史中找到正确的那一片。基准的失败把她推向了不同的观点：检索只是记忆的一个阶段。长期记忆还需要决定新信息如何改变旧信息、哪些陈述仍然有效、哪些决策取代早期的偏好、以及如何从历史中重构当前状态。

她现在关心的问题不再是**「agent 能记住我说过的话吗？」**而是**「agent 能否对『现在什么为真』维持连贯的理解——并解释它是如何到达那里的？」** 这就是 TypedMem 前进的方向。

# 《From retrieval to state: rethinking long-term memory for AI agents》的发芽报告

## 材料核心

作者在构建 TypedMem 与 ReliAgent Bench 时发现：主流「存储→嵌入→检索→回填」记忆管线在历史含多版本事实、矛盾与取代性决策时失效——向量搜索能正确取回「Alice 偏好早晨开会」，却答不了「现在该什么时候开会」。核心转向：记忆有不同语义（事件/状态/偏好/决策各有持久与取代规则），难点在历史解释而非存储；加一个 resolver 后过期记忆错误 37%→0、准确率 33%→78%，剩余瓶颈移向路由。由此提出面向状态的记忆模型（S₁─事件→S₂─决策→S₃─更新→现在）、五类可区分的失败（检索/路由/排序/裁决/表示），以及「原始历史作证据 + 小型结构化记忆层」的折中架构。

## 发芽 01：语义相关的记忆，可能恰恰是过时的答案

### 种子

那段 Alice 的例子之所以锋利：向量搜索「正确地」检索到了「Alice 偏好早晨开会」——这条记忆语义上完全相关，也完全不足以回答问题。检索的成功与答案的失败同时发生。

### 故事

更糟的是，「更多检索」不仅无助于事，还可能有害：系统会把新旧两条陈述一起返回，让下游在「哪条是当前的、后条是取代还是限定、是否临时例外、隐式决定能否推翻显式旧偏好」之间无所适从。作者的数据证实了这一点——瓶颈不在检索命中率，加入裁决器之前，37% 的失败是「拿着相关但过时的记忆作答」。

### Aha 瞬间

在会积累历史的系统里，「相关性」是关于过去语义的度量，而回答需要的是「当前有效性」的判断——这是两种不同的正确性，前者好测、后者的缺失恰恰是最隐蔽的失败模式。

## 发芽 02：把一件事压成一个分数，就再也找不到它坏在哪

### 种子

五类失败的划分——检索、路由、排序、裁决、表示——全部源自同一个动机：单一检索分数把性质不同的失败压扁成一个数字，压扁之后无从调试。

### 故事

文章的对照很鲜明：以前系统「答错了」，你只知道分数低；现在你能说出它属于哪种失败——证据没找到（检索）、搜错了记忆种类（路由）、找到了但被埋没（排序）、找到了但解读错（裁决）、压根没编码出所需的区分（表示）。作者说这套分解让 TypedMem 的调试「substantially more useful」。

### Aha 瞬间

可观测性的价值不在「看见失败」，而在「看见失败的种类」——度量的粒度决定了修复的方向。一个不能分解失败原因的系统，优化它就像蒙着眼睛调参。

## 发芽 03：全存与摘要是同一个陷阱的两端——真正要做的是选择什么进入「当前模型」

### 种子

无限存储「避免了在写入时做不可逆的决定」，代价是把难度全部推给检索与裁决，还放大无关上下文与矛盾；激进摘要则可能悄悄删掉日后重新解释某个事件所需的那个细节——两端都不解决问题，只是换个地方藏问题。

### 故事

作者的折中设计是一个双层结构：原始历史保留为可查的证据，小型结构化记忆层维护跨会话有用的东西——持久事实、变化状态、偏好、决策、目标及其更新关系。产物「不像笔记本，更像一个持续更新的用户或环境模型」——记忆系统的终态不是存档，是一份一直被维护的当前世界观。

### Aha 瞬间

「记住一切」和「总结一切」共享同一个错误假设：记忆是被动容器。真正有用的记忆必须主动维护一个「现在什么为真」的模型——存储只是它的证据链，不是它本身。
