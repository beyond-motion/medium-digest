# GitHub 仍在崩塌：2026 对开发者的信任做了什么

> 原文：[GitHub is still falling apart: what 2026 did to the developer's trust](https://medium.com/@patrick.szymkowiak/github-is-still-falling-apart-what-2026-did-to-the-developers-trust-2029368d45ae) — Patrick Szymkowiak

---

## 一年之后

2025 年 12 月我写过「GitHub 正在崩塌」，结尾下了一个预言：微软会把我们存在那里的代码变现，离开只是时间问题。

这是 2026 年的更新。同样的公开来源，多一年的数据。短版：**故障更糟了，GitHub 自己被黑了，Copilot 改成按量付费，训练政策变了，知名项目出走了。与此同时 GitHub 活动量史无前例。我认为这两件事相辅相成。**

## 数字再次爆炸

GitHub 10 月 28 日发布 Octoverse 2026（覆盖 2025 年 10 月至 2026 年 9 月，公私仓库）：**179 亿次 pushes**——超过 2024 与 2025 两年之和；**343 亿次 commits**——两年前的三倍多；**13 亿次合并 PR**——约每天 350 万；约 **450 亿次 Actions 任务**；**超过 2.25 亿开发者**（对照：2013 年 300 万、2018 年 3100 万、2023 年 1 亿、2025 年 1.8 亿）。

仓库总数曲线停在 2025 年——Octoverse 2026 没有给出总数。**Agent 解释了其中的大部分**：三月，17% 的 PR 以 Agent 的初稿起步；九月超过 40%，约一个月 1.1 亿次 PR。六月以来约 **55% 的 commit 流向当年新建的仓库**——去年我把这叫「坟场效应」，现在 Agent 正在写其中越来越大的部分。

## 故障

去年我的红线图是一套被自重压裂的系统；今年更糟。状态页比报告更难看：仅 2 月就列出 **37 起事件**——全系列最糟的月份。GitHub 四月解释过：容量翻 10 倍的计划始于 2025 年 10 月，到 2026 年 2 月他们知道需要 30 倍；现在公开的优先级是「先可用性、再容量、最后新功能」。与此同时 GitHub 正在迁往 Azure——11 月 9 日，151 个生产服务中的 **140 个**已跑在 Azure 上。

4 月与 8 月是最糟的月份，Actions 是坏得最多的服务。伤得最深的几次：

- **10 月 7 日**：github.com 写入故障，同日两次。超过 12,000 个组织的 push、登录与 API 写入失败。
- **8 月 6 日**：Actions 中断约 9 小时——托管与自托管 runner 一起挂，Pages 构建、Dependabot、Copilot agent 随之下线。
- **7 月 8 日**：带数据驻留的 Enterprise Cloud，Web、API、Actions 与 Git 不可用 7 小时。
- **4 月 23 日**：merge queue 出错，部分仓库发生错误合并。
- **4 月 1 日**：代码搜索 100% 的查询失败超过 2 小时。

## 价格

十二个月内三次价格变化，每次都朝「按使用付费」推进：

- **2026 年 6 月 1 日**：Copilot 转向按量计费——premium requests 被 AI Credits 取代，按 token 消耗。Pro 仍是 10 美元含 10 美元额度，Pro+ 39 美元含 39 美元。
- **2026 年 6 月 1 日**：Copilot 代码评审消耗 Actions 分钟数——在 AI Credits 之外、按正常 Actions 费率。
- **2026 年 1 月 1 日**：托管 runner 降价最多 39%——这条是好消息。
- **2025 年 12 月 16 日**：自托管 runner 每分钟 0.002 美元，原定 3 月 1 日实施——**让 GitHub 在你自己的机器上跑任务还要收钱**。反弹后推迟；今天自托管仍免费，但没有任何说法表示这个想法取消了。

Copilot 月费没变，但 Agent 全天跑起来，赠送的额度烧得很快。

## 数据

去年我写：微软的下一步是把过去变现——用冷存储里的代码训练，或者让你付钱换取代码远离 Copilot。以下是实际发生的：

3 月 25 日 GitHub 更新隐私声明与服务条款。**4 月 24 日起，Copilot Free/Pro/Pro+ 用户的交互数据默认用于训练 AI 模型，需要主动 opt-out。**范围之内：你的提示词、作为上下文送出的代码片段、你接受或修改的建议——**包括你在私有仓库里使用 Copilot 时做的工作**。范围之外：Copilot Business/Enterprise，以及「静止状态」（at rest）的私有仓库——GitHub 说这两个词是特意选的，因为你在使用时 Copilot 正在处理私有代码。

所以，他们做了。我一年前写他们会用我们的数据；一年后，模型训练对个人账户默认开启，私有仓库的代码在你使用 Copilot 的那一刻就进了训练。新隐私声明还允许 GitHub 与关联公司（包括微软）共享个人数据以开发 AI。我错的地方：冷存储——GitHub 说不训练「静止」的私有仓库；排除在训练外的正是付费组织方案——**这看起来很像我当时描述的「隐私溢价」**。个人账户的 opt-out 在 Copilot 设置里。

## 安全

2026 也是 GitHub 自己被黑的一年：

- **11 月 10 日，wfx-loot**：从 4,837 个账户偷来的 token 被用于通过 Actions 推送密钥窃取器；61,764 个仓库收到探针 PR；超过 1,800 个仓库的密钥与云凭据失窃。
- **10 月 8-9 日，GhostAction**：新一波，约 1,900 个账户被攻破、30,000+ 仓库被瞄准、瞄准 3,174 个 CI 密钥。
- **5 月 20 日**：GitHub 确认自己内部仓库被入侵——约 3,800 个内部仓库数据失窃，入口是一台员工笔记本和一个被投毒的 VS Code 扩展。GitHub 称无证据显示内部仓库之外的客户数据被碰；据 The Record 与 BleepingComputer，自称 TeamPCP 的团体宣称发动攻击并挂牌出售数据。
- **4 月 28 日，CVE-2026-3854**：单次 git push 就能在 GitHub 服务器上执行命令。Wiz 3 月 4 日报告，GitHub 当天修复 github.com，称从未被利用。

秋季那两波是另一种问题：攻击者用的是**从开发者那里偷来的 token**，GitHub 自身系统未被攻破；两次都瞄准 Actions 里存的密钥、云钥与 AI 供应商密钥。Agent 无处不在的时代，管道里的 token 更多，可偷的也更多。

## 谁走了

去年只有 Zig。今年更多了：

- **2026 年 4 月 28 日**：Ghostty。Mitchell Hashimoto（2008 年 2 月的 GitHub 第 1299 号用户）因故障把终端项目迁走，GitHub 上留只读镜像。他对 The Register 说：GitHub「已经不再是一个做正经工作的地方」。
- **2026 年 2 月 16 日**：Gentoo Linux 开始把镜像与 PR 迁往 Codeberg，理由：屡次被强行推 Copilot。
- **2025 年 11 月 26 日**：Zig 迁往 Codeberg，GitHub 仓库转只读。

公允地说，这不算大出血：Octoverse 显示开发者留了下来——8 月开过 PR 的人里超过 75% 在 9 月又推了代码。走的项目很少，但其中一个的带头人从 2008 年就在。

## 他们去哪

主要去 **Codeberg**——柏林的非营利组织，跑 Forgejo。11 月 24 日的数字：468,176 用户、777,379 个项目。算漏出吗？论量不算：GitHub 一年新增 4,500 万开发者，Codeberg 只增了约 27 万——但它翻了一倍多，而且只收开源项目。GitLab 是另一条路（更偏公司），注册用户超 5,000 万；营收同比 +25%、上季度 +21%——**GitHub 的故障没有体现在这些数字里。**

## 接下来会怎样

GitHub 不会消失：2.25 亿开发者在那里，Agent 每个月推更多代码。但对我来说，2026 回答了去年那个问题——**GitHub 现在是为 Agent 的量级而建，而我们的仓库在喂模型。**

如果你留下，这周该查三件事：①每一个碰公司代码的个人账户的 Copilot 训练设置；②你的 AI Credits 与 Actions 分钟数，别在账单上惊讶；③把仓库镜像到别处，并备好 Actions 挂掉时的部署方案；④你的 token 与 Actions secrets：轮换，删掉不用的。

如果你在乎价格、隐私、质量——去年我说那只是时间问题。**对 Gentoo 和 Ghostty，时间是 2026。**

（方法论：仅公开来源——GitHub 各月可用性报告、Octoverse 2026、官方 changelog、各家公告；漏掉的日期欢迎评论补充。）

# 《GitHub is still falling apart》的发芽报告

## 材料核心

Patrick Szymkowiak（8 min）对自家 2025 年 12 月预言的年度对账。数据：Octoverse 2026（179 亿 pushes 超 2024+2025 之和、343 亿 commits 三倍、13 亿合并 PR≈日 350 万、450 亿 Actions 任务、2.25 亿开发者）；仓库总数曲线停在 2025（不再公布）；Agent 起草 PR 占比 3 月 17%→9 月 40%+（月 1.1 亿）、55% commit 流向当年新建仓库（「坟场效应」）。故障：2 月 37 起事件全系列最糟；容量计划 10 倍→2 月知需 30 倍；151 生产服务 140 个已迁 Azure；最痛五案（10/7 写入故障波及 1.2 万组织、8/6 Actions 9 小时、7/8 Enterprise Cloud 7 小时、4/23 merge queue 错合并、4/1 搜索全挂）。价格：12 个月三变全朝按量付费（Copilot AI Credits、代码评审吃 Actions 分钟、托管 runner 降价 39%、自托管收费 0.002/分钟反弹后推迟未取消）。数据：4 月 24 日起个人账户交互数据默认训练（含私有仓库使用中代码，opt-out；「at rest」一词特意选的；关联公司含微软可共享）。安全：wfx-loot（4,837 账户 token、6.2 万仓库探针、1,800+ 失窃）、GhostAction（1,900 账户/3.2 万仓库）、5 月内部 3,800 仓库失窃（员工笔记本+投毒 VS Code 扩展）、CVE-2026-3854 git push RCE。出走：Ghostty（Hashimoto，2008 年 1299 号用户，「不再适合正经工作」）、Gentoo（被强推 Copilot）、Zig→Codeberg（用户翻倍至 46.8 万但 vs GitHub 年增 4,500 万）。结论：GitHub 为 Agent 量级而建、仓库在喂模型；留下者四查清单（训练设置/额度/镜像/轮换密钥）。

## 发芽 01：「坟场效应」的二期——Agent 时代平台指标的含义漂移

### 种子

「三月 17% 的 PR 以 Agent 初稿起步，九月超过 40%（月 1.1 亿次）」；「六月以来约 55% 的 commit 流向当年新建的仓库——去年我叫它坟场效应，现在 Agent 正在写其中越来越大的部分」；「仓库总数曲线停在 2025 年——Octoverse 2026 没有给出总数」。

### 故事

去年「坟场效应」指的是大量新建仓库半途而废；今年的数据让它长出了第二层含义：那 55% 流向新建仓库的 commit 里，越来越大的份额出自 Agent——也就是说，「增长」的构成正在从「人建项目」漂移为「Agent 批量产出的仓库与提交」。作者点出的细节是全文最锋利的一笔：Octoverse 2026 不再公布仓库总数——**当一个平台的增长叙事开始依赖 Agent 产量时，「有多少仓库」就从卖点变成必须藏起来的数字**。这与任何指标治理的规律一致：指标不再好看的第一反应是停止发布它。对开发者的实际含义：平台活跃度的信号价值在贬值——「2.25 亿人在用」不再等于「2.25 亿人在认真用」。

### Aha 瞬间

**当流量的生产者从人换成机器，平台的增长数字就从社区健康度变成了吞吐量报表——识别一个平台叙事切换的最快方法，是看它悄悄停止公布哪一个指标。**

## 发芽 02：「at rest」这个词是特意选的——隐私条款里的形容词防线

### 种子

「范围之外：私有仓库『静止状态』（at rest）——GitHub 说这两个词是特意选的，因为你在使用时 Copilot 正在处理私有代码。」以及「我错的地方：冷存储——排除在训练外的正是付费组织方案，这看起来很像我当时描述的『隐私溢价』。」

### 故事

这段是全文的条款解剖课。默认开启+opt-out+「个人账户才训练」+「静止不训练」四个设计叠加出一个精确的商业结构：免费与个人用户付数据、组织用户付钱、而「使用中」这个状态缝隙让私有代码实际进入处理管道——条款用形容词（at rest）而非名词（private repositories）划界，差异恰好等于 Copilot 工作时的全部流量。作者的诚实同样重要：他一年前预言对了一半（数据变现）、错了一半（冷存储）——对账式的写作让预言的可信度可以被审计。这与 11-23 金丝雀译文共享一个底座：**隐私承诺的真实边界写在条款的限定词里，而不是写在「你的代码是私有的」这种直觉里；审计限定词，或者像埋金丝雀一样实测，二选一。**

### Aha 瞬间

**隐私条款的攻防发生在形容词上——「at rest」「while using」「by default」每个修饰词都是一条数据流的闸门；读懂一个平台数据政策的方法是把每个名词的每个状态拆开问：这一格，训练吗？**

## 发芽 03：2008 年 1299 号用户的出走——平台信任的头部信号

### 种子

「Ghostty。Mitchell Hashimoto（2008 年 2 月的 GitHub 第 1299 号用户）因故障把终端项目迁走……他对 The Register 说：GitHub『已经不再是一个做正经工作的地方』。」以及作者的平衡：「这不是大出血——8 月开过 PR 的人里超过 75% 在 9 月又推了代码。走的项目很少，但其中一个的带头人从 2008 年就在。」

### 故事

作者刻意用「量」为 GitHub 辩护（年增 4,500 万开发者 vs Codeberg 增 27 万），同时用「质」给出反向信号：Hashimoto 这样的 18 年元老出走的理由不是价格也不是隐私，而是**故障**——当基础设施的可用性承诺失效，「严肃工作」的迁移门槛就被跨过了。这是平台信任衰减的经典序列：先丢容忍小故障的散户（无所谓），再丢把可用性当生产前提的重度用户（受伤），最后丢定义「正经工作」标准的头部人物（示范效应）。wfx-loot 与 GhostAction 补上了第三条腿：就算平台自己没被攻破，开发者 token 失窃的成本也由生态承担——「Agent 无处不在，管道里的 token 更多，可偷的也更多」是对 AI 化 DevOps 的安全税预警。

### Aha 瞬间

**判断一个基础设施平台是否在走下坡，不要看留存率（人会懒），要看头部元老在用什么理由离开——「故障让你没法做正经工作」这类离开，比「价格贵」的离开高一个警告等级。**
