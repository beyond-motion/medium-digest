# 为什么你的 batch size 是一个学习决策，而不是一个内存设置

> 原文：[Why Your Batch Size Is a Learning Decision, Not a Memory Setting](https://medium.com/@mahdi.nasermoghadasi/why-your-batch-size-is-a-learning-decision-not-a-memory-setting-cf1518d5e30a) — Mahdi Moghadasi

---

用 batch size 32 训练 1,000,000 个样本，你的模型每个 epoch 走 31,250 次优化器步。把 batch 提到 1,024，就只剩约 977 次——**模型改变主意的机会少了 32 倍。**

我们大多数人把 batch size 当硬件旋钮：一路调大到 GPU 显存爆掉为止，或者调到利用率曲线好看为止，然后再也不想它。**但 batch size 坐在学习算法的内部。**它决定每一步有多噪、你能得到多少步，并且与学习率一起，决定模型倾向于落进哪一类解。只改它而不动其他任何东西，你就已经悄悄换掉了那个实验。

## 一个 mini-batch 梯度到底是什么

梯度下降想要损失函数在整个数据集上的斜率。精确计算意味着每一步都把一百万个样本全跑一遍——太慢了。所以随机梯度下降（SGD）作弊：挑一小批随机样本，对批内每个样本的梯度取平均，把这个平均当作真实斜率的估计。

**随机样本的平均是一个带误差的估计。**平均值的标准误按样本量的平方根收缩——所以 batch 扩大 4 倍，梯度估计的噪声只减半。batch 1,024 相比 batch 32，噪声只少约 5.7 倍（√32），不是 32 倍。

**这是第一个意外：平方根。**batch 翻四倍，每步算力翻四倍，噪声却只减半。过了某个点，你在为「一个方向的稍微干净一点的估计」支付大量算术——而你本来就只打算沿它走一小步。

## 噪声是特性，直到某个点

把梯度噪声当成一个「大 batch 能修好的缺陷」很诱人。实践中，噪声在干活：噪的步子让权重抖动，**帮优化器逃出损失面上窄而陡的峡谷，漂向宽而平的谷地。**

Keskar 等人（ICLR 2017）报告：大 batch 训练倾向于收敛到更尖锐的极小值、泛化更差。后来的工作，比如 Hoffer、Hubara 和 Soudry 的「Train longer, generalize better」（2017）则论证：大部分差距来自大 batch 跑的更新次数更少，调整训练日程能关掉大部分差距。两种读法指向同一个实践事实：**大 batch 下，同样的 epoch 数不等于同样的学习量。**

一个有用的心智模型（Smith、Le 等人在 2018 年前后发展）：对 SGD 而言，重要的是**学习率与 batch size 的比值**。batch 翻倍而学习率不动，比值减半——更少的噪声、更小的有效探索。两个都翻倍，比值不变，训练动力学大体保持原样。

## 线性缩放规则，以及它在哪里失效

这个比值就是最著名的大 batch 配方背后的想法。Facebook 的 Goyal 等人（「Accurate, Large Minibatch SGD: Training ImageNet in 1 Hour」，2017）用 8,192 张图的 batch、跨 256 张 GPU 训 ResNet-50，匹配了常规小 batch 设置的精度。规则简单：**batch 乘 k，学习率也乘 k。**他们还在头几个 epoch 加了渐进 warmup——因为满额学习率打在刚初始化的网络上会炸。

规则有边界。OpenAI 的 McCandlish 等人（「An Empirical Model of Large-Batch Training」，2018）描述了一个由**梯度噪声尺度**决定的「临界 batch size」：低于它，batch 翻倍大致让你需要的步数减半；高于它，回报迅速衰减——烧更多算力，步数几乎不减。他们还发现这个临界值随训练推进、损失下降而增长——这是大模型训练常随时间 ramp up batch 的原因之一。GPT-3 论文就描述了训练早期逐步增大 batch，最大模型最终到约 320 万 token。

而且这条规则是对带动量的朴素 SGD 陈述的。**Adam 这类自适应优化器不干净地遵循它**；Malladi 等人（2022）的分析建议 Adam 系用学习率的平方根缩放做起点。无论哪边，**「放大 batch、学习率原地不动」是任何配方都不推荐的那个选项。**

## 它在真实项目里怎么咬你

最常见的版本不是深思熟虑的实验，而是一个配置。**按设备设置 batch size：2 卡 × 每卡 64，全局 batch 128。把同一份配置挪到 8 卡上求快，全局 batch 静默变成 512——学习率没动。**现在的运行是一个不同的实验，只是碰巧与旧实验共用一个 YAML 文件。如果它的最终精度低了一个点，没有人会想到怪硬件变更。

第二个版本是「利用率修复」。profiler 显示 GPU 在许多小 kernel 之间空闲，有人把 batch 从 32 提到 128，吞吐上跳。这对硬件是好事。**它同时也是 4 倍更小的学习率-批次比**（除非学习率跟着动），以及每 epoch 1/4 的步数。

**梯度累积是这里的诚实工具。**在 4 个 32 的 micro-batch 上累积梯度再步进，等价于一个 128 的 batch——你可以固定有效 batch、只改显存装得下什么。一个注意：**BatchNorm 仍按 micro-batch 算统计**，所以用它做归一化的模型在累积下并不严格等价。

## 我会检查什么

1. **你日志里的 batch 是不是全局的那个。**记录真正进入每次优化器步的数：每设备 batch × 设备数 × 累积步数。
2. **学习率是不是为那个全局 batch 调的。**batch 在学习率调优之后变过，那次调优就不再适用。
3. **你在按步还是按 epoch 对比运行。**两个 batch 不同、epoch 相同的运行，做的更新量不同。
4. **warmup 是否还盖得住训练的开头。**更大的 batch 配更大的学习率，通常更需要 warmup，不是更不需要。

## 为什么这件事重要

Batch size 之所以感觉像管道工程，是因为框架把它和数据加载器 worker 数放在同一个配置块里。**但你沿着走的那一步梯度是一个估计，batch size 决定这个估计有多好、你能用它走多少次、以及剩多少随机性把模型推向更好的地方。**像对待学习率一样对待它：一个你有意选择的超参数，每次运行都记录，只与它耦合的东西一起改动。

**你上次把训练任务挪到更多 GPU 时，跟着变的是全局 batch、学习率，还是都没有？**

# 《Why Your Batch Size Is a Learning Decision》的发芽报告

## 材料核心

batch size 被普遍误当硬件旋钮（调到显存爆/利用率好看为止），但它坐在学习算法内部：决定每步梯度估计的噪声、每个 epoch 的步数、以及（与学习率一起）模型落进哪类解。三个理论支柱：①标准误 √n 收缩——batch ×4 噪声只减半，1024 vs 32 仅 5.7 倍降噪，「为稍微干净的估计付 4 倍算术」；②噪声是特性——抖动帮优化器逃离窄陡谷漂向宽平谷（Keskar ICLR 2017 大 batch→尖锐极小值泛化差；Hoffer 2017 归因于更新次数；Smith/Le 2018 关键比值 LR/batch）；③线性缩放规则（Goyal 2017：batch×k 则 LR×k+warmup）有临界 batch size（McCandlish 2018 梯度噪声尺度，随训练推进增长→GPT-3 ramp 到 3.2M token），且 Adam 不干净遵循（Malladi 2022 建议平方根缩放）。实战两类静默 bug：per-device batch 配置（2 卡挪 8 卡全局 batch 128→512 同 LR=换了实验共用 YAML）、利用率修复（32→128 吞吐涨但 LR/batch 比缩 4 倍+步数 1/4）。梯度累积是诚实工具（BatchNorm 例外），四条检查清单（全局 batch 日志/LR 配套/按步对比/warmup 覆盖）。

## 发芽 01：√n 的暴政——降噪收益的边际递减为什么是平方根

### 种子

batch 翻 4 倍，梯度估计的噪声只减半；1024 vs 32 的 32 倍算力只买 5.7 倍降噪。平方根从哪来？

### 故事

来自统计学最基本的定理：样本均值的标准误正比于 1/√n。mini-batch 梯度就是一个样本均值——每个样本的梯度是随机变量，平均之后误差按平方根收缩。这意味着「信号质量」的定价曲线天然内凹：越往后，每单位降噪的算力成本越高。与「你本来就只打算沿这个方向走一小步」相乘，高倍 batch 的边际收益趋近于零——这正是 McCandlish 临界 batch size 的统计学根源（梯度噪声尺度低于步长所需的精度后，更干净的估计不再改变步向）。

### Aha 瞬间

**「更大的 batch」买的是更准的估计，但 SGD 要的不是准，是「够准的方向 + 足够多的步数」——两个需求在 √n 曲线上此消彼长，最优 batch 不是「显存允许的最大值」，而是这条边际曲线与步数预算的交点。**

## 发芽 02：噪声的功劳——为什么「干净的梯度」反而泛化更差

### 种子

Keskar 等人发现大 batch 训练收敛到更尖锐的极小值、泛化更差；噪声的抖动帮优化器逃离窄而陡的峡谷、漂向宽而平的谷地。

### 故事

这翻转了「噪声=缺陷」的直觉：损失面上有尖锐极小值（训练数据上完美、扰动一下就掉下去）与宽平极小值（扰动下稳健），而小 batch 的噪声恰好是逃离前者的探针——每一步的随机抖动让权重有机会「翻出」窄谷的壁。Hoffer 等人的修正（大部分差距来自大 batch 更新次数少，调整日程可关闭）则说明：噪声功劳有两个渠道——直接的（逃谷）与间接的（步数），后者可以通过训练日程补偿，前者不能。合成视角就是 LR/batch 比值：它同时控制噪声强度与有效探索半径。

### Aha 瞬间

**优化器需要噪声就像模拟退火需要温度——它是对损失面地形的随机探路预算；「消音」不是免费改良，而是拿掉模型的泛化探针；这也是为什么「放大 batch 不动 LR」是唯一没有任何配方推荐的选项——它同时抽走了探针和步数。**

## 发芽 03：静默换实验——「挪到 8 卡」如何变成一篇不同的论文

### 种子

2 卡 × 每卡 64 = 全局 batch 128；同一份配置挪到 8 卡，全局 batch 静默变 512、学习率没动——运行成了一个不同的实验，只是碰巧与旧实验共用一个 YAML。

### 故事

这类 bug 的阴险在于每一步局部都合理：per-device batch 是框架的标准字段、挪卡是为了快、吞吐上升证明改得好、精度掉一个点像是随机波动。没人把「硬件变更」列为实验变量，因为它在实验记录里根本不叫变量。梯度累积作为「诚实工具」的地位由此而来：它把「显存约束」与「学习决策」解耦——micro-batch 大小只管装不装得下，有效 batch 是你声明的学习参数，两者可以独立变化（BatchNorm 的 micro-batch 统计是残留的耦合点）。四条检查清单本质上是把「全局 batch」提升为需要显式记录、显式对齐的一等实验元数据。

### Aha 瞬间

**分布式训练里，硬件拓扑是隐藏的超参数——任何「挪机器/加卡/换卡」的决策都会经由 per-device 配置改写全局 batch，从而重写实验本身；可复现性的最小防线不是固定随机种子，而是把「进入每次优化器步的真实数字」记进每次运行的日志。**
