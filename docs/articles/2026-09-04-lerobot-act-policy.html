What I learned training an ACT policy for the LeRobot SO-ARM101

训练 LeRobot SO-ARM101 机械臂 ACT 策略，我学到了什么

引言

作者长期痴迷机器人，但多年来这个领域是碎片化的：市面上的机械臂不少，却很少有把硬件与现代机器学习绑在一起的统一框架和活跃开源社区。直到他在 Hugging Face 的 LeRobot 生态里发现了 SO-ARM101——一个低成本的 3D 打印机械臂，配标准化的数据集、易上手的模仿学习管线和活跃社区——他才真正踏入物理 AI。从最初的环境配置怪癖到训练出第一个 ACT（Action Chunking with Transformers）策略，过程中踩了很多官方文档没写的坑，本文把这些教训全部整理出来。

开发环境

作者在 MacBook 上用 pyenv 搭建 miniconda3-3.12 作为基础环境。官方文档的初始步骤是准确直观的，从 PyPI 安装 LeRobot 包及 CLI 脚本、Feetech 总线舵机控制所需的附加项：

  • pip install 'lerobot[core_scripts,feetech]'

需要几个相机？

布置物理工作区时，至少两个相机：

  • 腕部相机：提供目标物相对夹爪位置的细粒度视觉反馈——像戴了眼罩的赛马，视野窄，完全聚焦在操作点。
  • 顶部/俯视相机（鸟瞰）：给模型全局上下文，知道机械臂和物体在桌面上的位置。俯视视角可以避开侧装相机的盲区（机械臂身体会挡住视线）。
  • 前向基部相机（可选第三路）：任务复杂时，在底座上加一个前向相机提供深度透视，补充俯视与腕部视角。

作者见过用原装 15FPS 腕部相机配 MacBook 内置摄像头的省钱方案，但专用多相机布局的策略一致性要好得多。

硬件选型

  • 2 × InnoMaker 1080P USB2.0 UVC 相机：直接替换原装 15FPS 腕部相机，紧凑的外形和可选铝壳也方便装在臂座上当前向相机。
  • Pro HD 1080P/30FPS 网络摄像头 + 桌面三脚架：用于鸟瞰视角，放在旁边书架上即可调整高度和俯仰角，不必买专用夹具。

数据集录制与线程调优

录制示教片段时，每个相机至少分配两个编码线程（dataset.encoder_threads=2），否则遥操作过程会丢帧。作者的三相机方案给每相机 3 线程，占满 MacBook M3 Pro 的 9 个 CPU 核心。虽然 15FPS 可以缩小数据集体积、降低 CPU 开销，但现代 USB 相机原生默认 30FPS——所有传感器统一 30FPS 才能避免录制时的帧率不匹配问题。

降低分辨率换取训练速度

1080P 画面人眼看着爽，但高分辨率会让数据集膨胀、显存占用飙升、训练慢到爬行。ACT 的标准视觉骨干网不需要全高清细节来学习空间特征。把相机画面缩到 640x480 之类的低分辨率（训练与策略评估都用同一分辨率），存储需求和训练时间都会明显下降。

训练策略

第一个 ACT 策略要尽量消灭物理与视觉的可变性：用单色乐高块（或同色积木拼成的大块），放在干净纯色的背景前；目标容器选简单的盒子或碗，哑光单色。高反光、半透明、带花纹的物体会引入不必要的视觉噪声，让早期策略收敛难得多。

注意：作者最初用的是方块形 USB 充电器——这是个糟糕的选择。充电器插脚和不同面的纹理会随摆放角度产生显著的视觉变异，直接影响了夹爪抓取的一致性。

要训练多少步？

从经典深度学习转来的人都会问：训练步数怎么换算成 epoch？以三相机方案录制 100 条示教为例，通常得到约 45,000 行 Parquet 数据（每行对应一帧视频，含同步的相机图像与舵机关节状态）。若以 batch size 32 训练 20,000 步：

  • Epochs = 总步数 × Batch Size / 数据集行数 = 20000 × 32 / 45000 ≈ 14.2

一个 epoch 是完整过一遍训练数据。在标准 PyTorch/TensorFlow 工作流里，14 个 epoch 对视觉策略的泛化来说通常还差一点：25-50 个 epoch 是基础收敛的可靠基线。

任务复杂度 vs 数据集规模

epoch 数只是一个指标。底层数据覆盖不足时，训几百个 epoch 也不会变好。要让数据覆盖匹配任务复杂度，再配上足够的训练步数：

  • 固定起点+固定目标（低方差）：从固定的 A 点抓方块放进固定 B 点的容器——30 条示教、15 个 epoch 就能得到可用的基线策略。
  • 随机起点+固定目标（中方差）：乐高块可出现在工作区任意位置、容器固定——大约需要 100 条示教、30 个 epoch 来覆盖工作区分布。
  • 随机起点+随机目标（高方差）：块和容器每次演示都换位置——目标 250+ 条示教、约 50+ epoch，让 Transformer 编码器学到泛化的空间关系而不是背轨迹。

解读 L1 Loss

看训练曲线时，L1 Loss 是主要的收敛指标。没有通用及格线，但操作任务的 ACT 策略通常在 L1 Loss 降到 0.01-0.05 之间时开始出现可靠轨迹。0.02 实际意味着什么？它是模型预测轨迹块与真值遥操作动作在归一化关节空间上的平均绝对误差。注意它是所有自由度上的聚合平均：6 自由度臂上可能五个关节都接近零误差、唯独一个关键关节（腕部俯仰或夹爪闭合）误差偏高，而整体均值依然「好看」地停在 0.02。最终，真实世界跑策略永远是性能的真正检验——看着机械臂自主完成任务也是最 rewarding 的时刻。

我的实战

作者的目标：训练一个能把乐高块放进碗里的 ACT 策略，块和碗都可以放在工作区任意位置，目标成功率 75% 以上。数据在临时工作台上本地录制；因为 LeRobot 管线与 Hugging Face Hub 无缝集成，他把数据集推上去，在办公室的 NVIDIA DGX Spark 上跑资源密集的训练——更大 batch、更多步数，比 MacBook 上快得多。

  • v1（中方差基线）：50 条示教（约 21.5k 帧），乐高换位置、碗固定。20,000 步、batch 32（约 30 epoch），耗时约 8 小时，batch 32 占约 22GB 显存。L1 Loss = 0.074。
  • v2（全空间方差）：块和碗每次都换位置，新录 150 条，与旧数据合并共 200 条（约 83.5k 帧）。100,000 步、约 41 小时。L1 Loss = 0.052。
  • v3（补难点）：追加 125 条，专门覆盖别扭的摆放、桌面边缘、刁钻角度，合计 325 条（约 141k 帧）。250,000 步、约 104 小时。L1 Loss = 0.040，稳定达成 75%+ 成功率。

104 小时的训练听起来夸张，但 DGX Spark 的算力让 Transformer 在刁钻的空间边界上平滑泛化，稳稳达到目标。

下一步

SO-ARM101 的「机器人操作 hello world」只是起点。作者接下来想挑战可变形物体操作（比如用 ACT 策略叠衣服），也想试 Vision-Language-Action（VLA）模型——Hugging Face 的 SmolVLA、Physical Intelligence 的 Pi、NVIDIA 的 GR00T——看通用多模态骨干网如何处理零样本空间推理和自然语言任务提示。工具层面，他期待 NVIDIA Isaac Sim 等仿真环境原生支持 macOS（目前仅限 Linux/Windows + NVIDIA RTX），以及一台由 DGX Spark 或 AMD Ryzen AI Halo 驱动的本地 AI 工作站。

《What I learned training an ACT policy for the LeRobot SO-ARM101》的发芽报告

材料核心

核心观点：具身智能的第一次成功，取决于你把「视觉世界」收拾得多干净，以及数据覆盖是否匹配任务方差——算力可以买，视觉噪声和覆盖缺口省不掉。

发芽 01：策略不好，先别怪训练，先看它眼里的世界

种子

作者最初用方块形 USB 充电器当抓取目标，后来换成单色乐高块。

故事

同一个管线、同样的训练，充电器版本的抓取一致性就是上不去。原因不在模型：充电器的插脚和不同面的纹理，随着摆放角度变化制造了大量视觉变异，模型看到的每次都是「不太一样的东西」。

Aha 瞬间

调策略的第一反应往往是改超参数，而本文的第一课是物理世界的事：视觉噪声是策略的天花板，而且它是在数据采集那天就定死的。换一个更「干净」的目标物，比多训 100 小时更便宜。

发芽 02：平均值会撒谎——L1 Loss 0.02 的陷阱

种子

L1 Loss 是所有自由度上的聚合平均绝对误差。

故事

6 自由度机械臂上，五个关节可能都逼近零误差，唯独腕部俯仰或夹爪闭合这一个关键关节误差很高——整体均值依然可以「好看」地停在 0.02。而夹爪恰好多半正是任务成败的那个关节。所以作者的结论是：真实世界的 rollout 才是唯一检验。

Aha 瞬间

这条对所有系统评估都成立：聚合指标会掩盖单点失败，而失败往往恰好发生在那个单点上。看平均之前，先看分布和最差的维度。

发芽 03：瓶颈常在覆盖，不在步数

种子

文中给出三档任务方差与数据量的对应：固定→30 条/15 epoch；随机起点→100 条/30 epoch；双随机→250+ 条/50+ epoch。

故事

作者的迭代路径不是一路加大步数：v1 先用 50 条证明单目标可行，然后发现真正卡住泛化的是「块和碗都动起来」的覆盖缺口，于是补录 125 条专门覆盖桌面边缘、别扭角度这些难点，才把 L1 从 0.052 推到 0.040。

Aha 瞬间

训练步数解决的是「学没学会」，数据覆盖解决的是「见没见过」。当模型在训练分布内表现良好、换个位置就崩，该加的是数据多样性，不是 epoch。
